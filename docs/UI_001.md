## 1. 최종 권고: 안내형 그래프 작업실

### 1.1 하나의 작업 모델, 세 개의 화면

메인 화면은 **안내형 그래프 작업실**로 만듭니다. 초보자는 안내 패널에서 설계 언어로 입력하고, 시스템이 같은 그래프의 노드와 연결을 생성합니다. 숙련자는 그 그래프를 펼쳐 직접 수정합니다. 두 모드가 서로 다른 설정을 보유하면 안 됩니다.

| 화면 | 사용자가 답하는 질문 | 주요 구성 |
|---|---|---|
| 작업실 `/` | 무엇을 어떻게 해석할 것인가? 지금 어디까지 진행됐는가? | 형상 미리보기, 물리 구성 그래프, 조건 패널, 실행·비교 목록 |
| 결과 뷰어 `/api/runs/{name}/viewer` | 언제, 어디가, 얼마나 변형·개방됐는가? | 판단 문장, 3D 재생, 곡선, 이벤트, 설계안 비교 |
| 리포트 `/api/runs/{name}/report` | 이 결과를 어느 범위에서 믿고 사용할 수 있는가? | 조건·재료·메쉬·게이트·검증 근거·산출물 |

제출 전용 화면과 모니터 전용 화면을 추가하지 않습니다. 제출 후에도 작업실의 결과 노드와 실행 패널에서 진행을 확인합니다. 완료되면 뷰어를 여는 명확한 버튼을 제공합니다. 안내 단계, 가져오기 대화상자, 비교 패널은 위 세 화면의 하위 상태입니다.

### 1.2 UI 설계의 우선순위

1. 처음 보는 설계자가 **자신의 설계 질문을 고를 수 있어야** 합니다.
2. STEP에서 알 수 없는 조건을 최소한의 질문으로 확인해야 합니다.
3. 실행 전에 형상·하중·고정·예상 시간을 한 화면에서 이해해야 합니다.
4. 결과는 숫자 목록보다 **판단 문장 → 핵심 지표 → 곡선·변형 → 근거** 순서로 읽혀야 합니다.
5. 값 하나를 바꾸어 이전 결과와 비교하는 동작이 첫 실행보다 쉬워야 합니다.

‘쉬움’을 확인 절차의 삭제로 구현하지 않습니다. 재료와 고정 조건을 조용히 추정하면 사용자는 다른 문제를 해석한 결과를 믿게 됩니다. 대신 검증된 템플릿, 시각적 선택, 출처가 보이는 기본값을 제공합니다.

### 1.3 제품 약속의 표현

- 소개 문구: **“셀 형상을 넣고, 설계 방향을 빠르게 확인하세요.”**
- 보조 문구: “압착·강도·벤트 개방을 초기 설계 단계에서 검토합니다.”
- 시간: “목표: 4코어 노트북에서 1건 30분 이내.” 실제 예상치는 케이스별로 표시합니다.
- 정확도: “검증된 조건에서 주요 지표의 정밀 해석 대비 오차 10% 이내를 목표로 합니다.”
- 모든 결과에 `정확도 90%`, `±10% 보장`, `안전함`을 붙이지 않습니다.

**최신 기록 정정:** LC-6 스코어 메쉬 0.5 mm의 엔진 시간은 2,361초, 약 39분입니다. 0.3 mm 기준 결과와의 차이는 약 5%로 정확도 목표에는 들지만 30분 시간 예산은 넘습니다. 0.3 mm 엔진 시간은 약 7.3시간입니다. 이전의 ‘0.5 mm 약 25분, 정답 메쉬’ 기록은 최신 GOAL에서 정정됐습니다. 현재 두 목표를 함께 만족하는 예산 메쉬는 탐색 중입니다. UI는 **정확도 근거 있음 / 시간 목표 초과**를 분리 표시하고 0.7 mm 등의 탐색 후보를 검증 완료 기본값으로 승격하지 않습니다. 모든 STEP·재료·하중에 일반화하지 않으며 0.3 mm를 ‘고품질 권장’ 기본값으로 올려놓지 않습니다.

## 2. 현재 구현과 필요한 변화

아래는 기준 커밋의 소스 정적 검토입니다. 실제 브라우저 사용성 시험을 수행했다는 의미는 아닙니다.

| 확인된 현재 구조 | 사용자 관점의 문제 | 권고 변경 |
|---|---|---|
| `index.html`에 노드 편집기, 브라우저의 `compileGraph()` | 처음부터 해석 구성 지식이 필요함 | 목적별 템플릿으로 그래프 자동 생성 |
| STEP 입력이 `step_path` 텍스트 필드 | 파일만 가진 사용자는 서버 경로를 모름 | 업로드·가져오기 및 형상 확인 흐름 구현 |
| `runGraph()`가 케이스 저장 후 실행, `Monitor` 이동 | 작업 맥락이 끊김 | 결과 노드·실행 패널을 같은 작업실에 통합 |
| `mesh × material × load` 조합 생성 | 다중 연결만으로 실행 수가 크게 늘어남 | 제출 전 조합표·건수·총 시간을 필수 표시 |
| 대기열이 케이스 파일명을 보유하고 작업 시작 시 파일 로드 | 대기 중 파일 수정이 실행 입력에 영향을 줄 수 있음 | 제출 시 불변 입력 스냅샷 생성 |
| 그래프 로드 시 미지의 노드 타입을 건너뜀 | 다른 버전의 설정이 조용히 사라질 수 있음 | 읽기 전용 경고·원본 보존·명시적 변환 |
| 솔버 노드 LC 선택 목록에 LC-1/2/3만 표시 | 템플릿·실제 지원 범위와 표시가 어긋날 여지 | 서버의 capability를 단일 근거로 사용 |
| `/api/runs`에 실행 로그·진행·일부 결과 지표 | 목표 판정·신뢰 수준·추정 근거가 부족함 | 버전 있는 실행·결과 메타데이터 확장 |

**우선 구현 대상은 구조·강도와 벤트 파단입니다.** 전기저항·열 해석은 준비된 것처럼 활성화하지 않습니다. 개별 하중 유형의 실행 가능 여부도 백엔드가 현재 지원하고 검증한 템플릿으로 한정합니다.

## 3. 정보 구조와 화면 배치

### 3.1 데스크톱 기본 배치

기준 뷰포트는 1440 × 900 CSS px이며, 1366 × 768에서도 제출 버튼과 현재 입력 항목이 보여야 합니다.

| 영역 | 권고 크기 | 내용·동작 |
|---|---|---|
| 상단 프로젝트 바 | 높이 56 px | 프로젝트명, 저장 상태, 열기, 새 해석, 도움말 |
| 왼쪽 구성 패널 | 폭 224 px, 접기 가능 | 목적, 부품 목록, 안내 단계, 실행 목록 진입 |
| 중앙 작업 공간 | 남는 폭, 최소 480 px | 위 형상 미리보기 / 아래 연결 그래프, 기본 비율 60:40 |
| 오른쪽 속성 패널 | 폭 320 px | 선택한 단계·부품·노드의 설계 입력 |
| 하단 실행 바 | 높이 최소 64 px | 확인 필요 수, 예상 시간, 실행 건수, 주요 실행 버튼 |
| 실행 목록 패널 | 중앙 아래에서 확장 | 대기·실행·완료 행, 결과 비교 선택; 독립 화면 아님 |

중앙 분할선은 조절할 수 있습니다. `형상과 그래프`, `형상 크게`, `그래프 크게`의 세 보기 버튼을 제공합니다. 초기 그래프는 중요 물리 구성과 접힌 해석 설정만 보여줍니다. 솔버의 수십 개 필드를 노드 안에 펼쳐 화면을 채우지 않습니다.

현재 단계가 바뀌면 관련 부품을 강조하고 해당 노드를 선택합니다. 사용자가 카메라를 조작한 뒤에는 작은 필드 수정마다 카메라를 초기화하지 않습니다. `선택 부품 보기`로 명시적으로 이동합니다.

### 3.2 폭에 따른 적응

| 폭 | 배치 |
|---|---|
| ≥ 1280 px | 위의 3열 작업실 |
| 1024–1279 px | 왼쪽 패널을 아이콘+접이식 목록으로 축소, 속성 패널 300 px |
| 768–1023 px | 중앙 한 영역과 토글식 속성 패널. 그래프·형상 탭 제공 |
| < 768 px | 결과 열람 우선. 작업실은 단계·노드 목록으로 제공하고 복잡한 연결 편집은 데스크톱 권장 |

모바일에서 뷰어 재생·회전·확대, 곡선 읽기, 결과 비교 요약, 리포트 열람은 필수입니다. 작은 화면에서 해석 제출을 지원하지 않는 최초 버전이라면 버튼을 숨겨 버리지 말고 “해석 설정은 PC에서 이어서 할 수 있습니다”와 저장된 프로젝트 이름을 보여줍니다. 모바일 지원 완료를 데스크톱 캔버스 축소로 판단하지 않습니다.

### 3.3 처음 열었을 때

빈 무한 캔버스 대신 중앙에 시작 영역을 제공합니다.

- 제목: **“어떤 셀을 검토할까요?”**
- 주 선택: `치수로 빠르게 시작` — “원통형·각형 캔을 치수로 만듭니다.”
- 동등한 진입 선택: `STEP 파일 가져오기` — “.stp 또는 .step 파일을 선택하세요.”
- 보조 선택: `저장한 그래프 열기`, `예제로 둘러보기`.

파라메트릭이 권장 경로임을 짧게 표시하되 STEP 진입을 메뉴 안에 숨기지 않습니다. 예제는 `예제 형상·예제 조건`을 지속 표시하고, 예제 결과를 사용자의 실제 해석 결과처럼 보여주지 않습니다.

## 4. 첫 실행: 네 단계 안내

안내는 오른쪽 속성 패널에서 진행합니다. 이동 가능한 단계명과 완료 상태를 왼쪽에 표시합니다. 이전 단계로 돌아가도 입력은 보존합니다.

| 단계 | 사용자 행동 | 시스템 처리 | 완료 기준 |
|---|---|---|---|
| 1. 형상 | 파일 선택 또는 치수 입력 | 서버 형상 읽기, 부품·치수 미리보기 | 지원 형상, 단위·주요 부품 확인 |
| 2. 알고 싶은 것 | 압착·축방향 강도·벤트 개방 등 선택 | 지원 템플릿으로 그래프 구성 | 실행 가능한 목적 선택 |
| 3. 조건 | 재료, 힘을 가하는 곳, 고정 조건, 목표 확인 | 시각적 하중·고정 미리보기, 기본값 적용 | 필수 미확인·물리적 모순 없음 |
| 4. 실행 확인 | 조건 요약 확인 후 실행 | 사전 검사, 시간 추정, 입력 스냅샷 | 실행 ID와 대기열 등록 확인 |

3분 기준은 **준비된 지원 형상과 템플릿으로 첫 제출까지**의 사용성 목표입니다. 설치, 임의 CAD 복구, 지원하지 않는 재료 모델 개발까지 3분을 약속하지 않습니다. 파일 가져오기 시간은 사용자 체감 시간에 포함해 측정하고 별도로 기록합니다.

### 4.1 입력의 출처를 표시하는 네 상태

| 출처 | 표시 | 의미 |
|---|---|---|
| 형상에서 추출 | `형상에서 읽음` | 치수·부품·단위 등 실제 추출값. 실패하면 미확인 |
| 검증된 템플릿 | `추천값 · 근거 보기` | 적용 범위와 템플릿 버전을 보유한 기본값 |
| 사용자 지정 | `직접 입력` 또는 `확인함` | 사용자가 지정·확인한 값 |
| 정보 없음 | `확인 필요` | 필수이면 실행 불가. 선택 지표이면 해당 판정만 불가 |

모든 기본값마다 확인 버튼을 누르게 하지 않습니다. 치명적인 오해를 만들 수 있는 재료·주요 부품 역할·하중 방향·지지 조건은 단계 요약에서 묶어 확인합니다. 다른 형상이나 해석 목적으로 바꾸면 영향받는 확인만 해제합니다.

## 5. STEP 가져오기와 형상 준비

### 5.1 파일을 가진 사람의 진입 장벽 제거

드롭 영역과 `파일 선택` 버튼을 함께 제공합니다. 서버 경로는 기본 UI에서 제거하고 고급 가져오기에만 남깁니다. 허용 확장자와 서버에서 설정한 크기 제한을 업로드 전에 표시합니다. 제한 수치는 capability 응답을 사용하며 프런트엔드와 서버가 다른 제한을 갖지 않습니다.

상태는 `전송 중 → 형상 읽는 중 → 부품 확인 → 준비됨`입니다. 전송률과 형상 처리 진행률을 섞지 않습니다. 서버가 진행률을 제공하지 않으면 “형상을 읽고 있습니다 · 경과 12초”처럼 표시합니다. 파일이 준비되지 않았는데 가짜 3D 모델을 보여주지 않습니다.

업로드 취소는 업로드/가져오기 작업만 취소합니다. 프로젝트의 이전 형상은 새 형상 검토가 완료될 때까지 유지합니다. 동일 이름 파일도 asset ID와 내용 해시로 구분합니다.

### 5.2 형상 확인 카드

최초 화면에는 파일명, 단위, 외형 치수, 솔리드 수, 인식한 부품 역할을 표시합니다. 부품 목록 선택과 3D 강조를 동기화합니다.

| 정보 | 처리 규칙 |
|---|---|
| 단위 | 파일 정보 우선. 불명확하거나 비현실적인 크기이면 mm/m 등 확인 요청. 조용한 배율 보정 금지 |
| 형상 방향 | 좌표축과 기준면 표시. 자동 장축 추정은 제안이며 하중 방향 확정과 구별 |
| 솔리드와 부품 | ‘솔리드 15개’가 ‘실제 부품 15개’임을 가정하지 않음 |
| 두께 | 영역별 검출 가능 여부 표시. 하나의 두께를 전체 형상에 무조건 적용하지 않음 |
| 캔·캡·벤트 | 인식 결과를 제안하고 선택 부품을 강조. 불명확하면 사용자 역할 지정 |
| 재료 | STEP 이름·색상으로 해석 재료를 확정하지 않음 |
| 용접·접촉 | 맞닿아 있다는 사실과 용접 연결을 구분. 해석 템플릿의 연결 가정을 확인 |
| 스코어 잔여 두께 | 실제 형상에 없거나 추출 불가이면 입력 필요. 홈 폭과 잔여 두께를 별도 취급 |

일반 STEP을 읽을 수 있다는 사실과 해당 어셈블리를 검증된 파이프라인으로 해석할 수 있다는 사실을 구분합니다. 기존에 있는 얇은 다중 솔리드 처리 보조 기능도, 연결된 실행 유형과 검증 근거가 없으면 범용 지원으로 광고하지 않습니다.

### 5.3 복잡한 형상과 단순화

원본과 해석용 형상을 전환할 수 있게 합니다. 제거·치환된 특징은 수량과 위치로 표시합니다. 원본 파일을 덮어쓰지 않습니다.

- 표시 예: “해석용 형상에서 작은 모서리 12개를 단순화했습니다. 변경 부위 보기.”
- 중복 표면, 분리된 필수 부품, 기준 대비 질량 오차 ±10% 초과 등의 모델 유효성 실패는 실행을 막습니다.
- 파라메트릭 치환이 필요하면 “이 STEP을 그대로 해석”과 구분되는 선택으로 제안합니다. 치수·형상 차이와 제외 부품을 확인한 후 별도 파생 모델을 만듭니다.
- 지원하지 않는 형상은 “다른 파일을 넣어보세요”로 끝내지 말고 문제가 되는 부품과 가능한 다음 동작을 안내합니다.

실패 문구 예: **“벤트에 연결되지 않은 부품이 2개 있습니다. 강조된 부품의 역할과 연결을 확인하세요.”** 버튼: `문제 부품 보기`.

## 6. 해석 유형별 설계 입력

### 6.1 목적 카드

| 카드 | 짧은 설명 | 기본 결과 |
|---|---|---|
| 눌렀을 때의 반력 | “옆면이나 지정 위치를 눌렀을 때 필요한 힘을 봅니다.” | 하중–변위, 최대 반력, 지정 변위 반력 |
| 축방향 압궤·강도 | “위아래로 눌렀을 때 접힘과 지지 하중을 봅니다.” | 하중–변위, 평균/최대 하중, 흡수 에너지 |
| 벤트 개방 | “내압이 올라갈 때 벤트가 언제 얼마나 열리는지 봅니다.” | 개방 압력, 개방 면적, 압력–시간 |
| 전기저항 | `준비 중` | 활성 실행 버튼 없음 |
| 열 응답 | `준비 중` | 활성 실행 버튼 없음 |

카드의 명칭과 지원 여부는 서버 템플릿 목록과 매핑합니다. LC 번호는 보조 정보입니다. 목적 카드가 서버의 `load_case` 값을 독자적으로 추측하면 안 됩니다. 압입·비딩 등 추가 템플릿은 실제 지원 시 `더 많은 하중 방식`에 노출합니다.

### 6.2 공통 입력

| 입력 | 기본 UX | 검증·도움말 |
|---|---|---|
| 재료 | 명칭·상태가 보이는 검색 선택 | 재료 카드 출처, 두께/온도/변형률속도 적용 범위, 검증 상태 |
| 판 두께 | mm 단위 수치 + 형상 부위 강조 | 0 초과. 지역 두께와 전체 두께 구분 |
| 지지·고정 | 그림이 있는 옵션 + 선택 부위 | “이 면은 움직이지 않습니다”와 3D 고정 아이콘 |
| 하중 방향 | 3D 화살표, 면 선택, `반대 방향` | 숫자 벡터는 고급 설정. 방향을 문장으로 반복 |
| 설계 목표 | 선택 입력, 지표·하한·상한 | 없으면 해석 가능하나 ‘목표 이내’ 판정 없음 |
| 검토 이름 | 자동 제안 + 수정 | 사용자 표시명과 파일/실행 ID 분리 |

수치 필드 오른쪽에 단위를 고정 표시합니다. placeholder만으로 단위를 전달하지 않습니다. 입력 중 `-`, 소수점 등 미완성 상태는 허용하고, blur 또는 다음 단계에서 검증합니다. 잘못된 값을 0이나 기본값으로 조용히 바꾸지 않습니다. 사용자가 붙여 넣은 `0.5 mm`는 명확한 동일 단위일 때 정규화하고, 다른 단위 변환은 변환값을 표시합니다.

### 6.3 압착·압궤 입력

| 기본 노출 | 제어 | 설명 |
|---|---|---|
| 누르는 도구 | 평판/지원되는 지그의 그림 선택 | 선택한 도구 형상을 미리보기 |
| 누르는 위치·방향 | 면 선택 또는 기준축 선택 | “위에서 아래로 누름” 등 문장 |
| 누르는 거리 | mm 수치 | 스트로크 대신 사용. 고급 도움말에 원어 병기 |
| 고정 방식 | 바닥 고정·지그 등 지원 옵션 | 과구속 여부를 사전 검사 |
| 공구 반경 | 해당 도구일 때만 표시 | 조건부 필드 |
| 목표 반력 | 선택 입력 N 또는 kN | 최대/평균/특정 변위 지표를 명확히 선택 |

솔버용 가속 속도·램프·접촉 페널티·질량 스케일링은 기본 화면에서 숨깁니다. 실제 시험 속도와 수치적 가속 조건은 별도 메타데이터입니다. 지원하지 않는 속도 의존성을 반영한 것처럼 표시하지 않습니다. 스트로크 제어만 지원하는 템플릿에 하중 제어 옵션을 만들어 놓지 않습니다.

평균 하중은 어느 변위 구간의 평균인지 필수 표시합니다. 흡수 에너지는 적분 구간과 단위를 함께 표시합니다. `absorbed_energy_mJ`를 J로 표시할 때는 서버/공통 변환 함수에서 1,000으로 나눈 값을 사용합니다.

### 6.4 벤트 개방 입력

| 기본 노출 | 단위·표현 | 검증 |
|---|---|---|
| 캔·캡·벤트 역할 | 선택 부품 하이라이트 | 부품 누락·잘못된 연결 확인 |
| 벤트 길이·폭 | mm | 실제 또는 파라메트릭 정의 여부 |
| 포일 두께 | mm | 양수, 재료 카드 적용 범위 |
| 스코어 잔여 두께 | mm, 작은 단면 설명 그림 | 0 초과, 포일 두께 이하. 스코어 폭과 구분 |
| 스코어 패턴 | 지원 패턴 썸네일 | 표시 패턴과 실제 생성 패턴 일치 |
| 포일 재료 | 카드 선택 | 파단 모델 검증 정보 |
| 지지 상태 | 단독 셀/모듈 구속 등 지원 템플릿 | 넓은 면 구속을 조용히 적용하지 않음 |
| 최대 가압 압력 | MPa | 목표 범위까지 평가 가능한지 확인 |
| 목표 개방 압력 | 하한–상한 MPa, 선택 | 목표 상한 > 하한 |

메쉬는 서버의 검증된 프리셋 정책으로 선택합니다. 현재 LC-6의 **0.5 mm**를 제공할 경우 “정확도 비교 근거 있음 · 엔진 실측 약 39분 · 시간 목표 초과”로 표시해야 합니다. 30분·10%를 동시에 만족하는 프리셋이 확정되기 전에는 “30분 목표 기본 설정” 배지를 붙이지 않습니다. 탐색 중인 0.7/0.65 mm 등은 실제 등록된 후보만 고급 검토에 노출하고 검증 대기 상태를 유지합니다. 상세 설정에는 값·측정 범위·근거를 공개합니다. 다른 영역 메쉬 크기와 스코어 메쉬 크기는 구분합니다.

파단 변형률은 초보자의 필수 입력에서 제거하고 재료 카드에 속하게 합니다. 검증되지 않은 사용자 재료를 허용한다면 실행 결과에 `재료 검증 미확인`을 표시합니다. ‘실행 가능’이 ‘정확도 목표 검증됨’을 뜻하지 않습니다.

‘개방’ 이벤트는 후처리 정의를 사용합니다. 첫 요소 파단, 유효 개방 면적 기준 도달, 완전 개방을 하나의 사건으로 섞지 않습니다. 면적 기준이 사용되면 기준값·분모 면적·정의 버전을 결과에 저장합니다. 특정 면적 비율을 보편적 물리 법칙으로 표현하지 않습니다.

### 6.5 미지원 유형

전기저항·열 카드에는 필요한 입력의 개략만 설명할 수 있습니다. 전기 전도도·접촉저항·단자 조건 또는 열물성·발열·주변 온도·냉각 조건이 STEP 외에 필요함을 표시합니다. 백엔드가 준비될 때 capability로 활성화하며, 구조 해석 버튼을 다른 이름으로 재사용하지 않습니다.

## 7. 그래프 상호작용 규칙

### 7.1 설계 구조와 계산 흐름의 표현

물리 구성은 `캔 → 캡 → 벤트`처럼 실제 포함·연결을 설명합니다. 해석 준비는 `메쉬·재료·하중 → 실행 → 결과`로 나타냅니다. 선의 의미를 범례와 포트 이름으로 구분합니다. 모든 선을 용접으로 이해하게 만들어서는 안 됩니다.

| 노드 | 접힌 상태의 요약 | 펼침/선택 시 |
|---|---|---|
| 형상 | 파일명 또는 외형 치수, 확인 상태 | 부품·단위·두께 |
| 캡 | 부품명, 연결 가정 | 용접/연결 설명과 근거 |
| 벤트 | 패턴, 잔여 두께 | 형상·재료·스코어 입력 |
| 하중 | “아래로 20 mm” 또는 “내압 최대 … MPa” | 위치·방향·조건 |
| 해석 설정 그룹 | “4코어”와 시간 목표 충족/초과/미확인 상태 | 메쉬·접촉·솔버 내부 노드 |
| 실행 | 사전 검사, 예상 시간, 건수 | 입력 스냅샷 요약 |
| 결과 | 진행 상태 또는 판단 문장 | 실행 목록·뷰어·리포트 |

‘해석 설정 그룹’은 표시상의 그룹이며 기존 노드를 소실시키는 새로운 물리 모델이 아닙니다. 필수 노드가 접혀 있어도 오류 배지와 실행 차단 이유를 상위 그룹에 전달합니다.

### 7.2 편집

- 클릭은 선택, 노드 제목 드래그는 이동, 빈 공간 드래그는 캔버스 이동입니다.
- 캔버스 확대는 전용 버튼과 캔버스 내부의 명시적 제스처로 제한합니다. 페이지 전체 스크롤을 가로채지 않습니다.
- 호환 포트만 강조하고 연결 직전에 타입·다중성·순환을 검증합니다.
- 단일 입력 포트에 새 연결을 넣으면 기존 연결 교체 여부를 보여줍니다. 삭제부터 하고 실패하지 않습니다.
- 드래그 없이 `연결 추가 → 대상 노드 → 입력 선택`으로 같은 작업이 가능해야 합니다.
- 삭제 시 영향받는 실행 구성을 알려주고 실행 취소를 제공합니다. 결과 기록은 노드 삭제와 함께 지우지 않습니다.
- `Ctrl/Cmd+Z`, 재실행, 선택 삭제, 선택 보기, 전체 보기 지원. 텍스트 입력 중 단축키를 탈취하지 않습니다.
- 자동 정렬은 사용자의 명시적 요청 또는 최초 생성 때만 수행합니다.

### 7.3 비교안과 조합 실행

초보자의 기본 비교 동작은 **`이 조건에서 하나 바꿔 비교`**입니다. 선택한 파라미터를 복제하여 A/B 두 실행을 만듭니다. 기본값은 두 케이스이며 전체 조합 생성은 고급 동작입니다.

예: 스코어 잔여 두께 `0.03 → 0.04 mm`. 실행 전 차이표에 이 한 줄만 보여주고 동일 조건은 접습니다. 이는 UI 예시이며 추천 설계 수치가 아닙니다.

다중 연결의 현재 의미는 곱집합입니다. 메쉬 2 × 재료 3 × 하중 2이면 **12건**임을 표시합니다. `같은 순번끼리 비교`를 도입할 경우 별도 모드와 길이 검증을 추가해야 하며 기존 곱집합 의미를 조용히 변경하지 않습니다.

제출 전 조합별 이름·변경값·시간·검증 상태를 보여줍니다. 1건 25분 × 12건이면 총 약 5시간에 대기·준비 시간이 더해짐을 표시합니다. `30분 이내` 배지를 배치 전체에 붙이지 않습니다.

### 7.4 저장과 버전

자동 저장은 마지막 편집 이후 짧은 지연을 두어 수행하며 `저장 중 / 저장됨 / 저장 실패`를 표시합니다. 명시적 저장도 제공합니다. 네트워크 실패 시 현재 편집을 보존하고 재시도합니다.

그래프 JSON에 스키마 버전과 개정 번호를 둡니다. 미지의 노드·필드는 보존하고, 이해할 수 없는 그래프는 읽기 전용으로 열어 실행을 막습니다. 변환은 복사본에 수행합니다. 여러 탭의 충돌은 마지막 저장으로 덮어쓰지 않고 서버 개정 비교로 검출합니다.

## 8. 실행 전 검사와 시간 예산

### 8.1 실행 바

정상 예: **“1건 · 예상 22–28분 · 4코어”** / 버튼 `해석 시작`.
대기 중 작업이 있으면 “시작까지 약 … / 실행 약 …”를 나눕니다. 근거 없는 숫자는 `추정 준비 중` 또는 `이 형상은 시간 추정 자료가 부족합니다`로 표시합니다.

시간 표시의 범위를 고정합니다.

- 해석 1건 시간: 실행 시작부터 형상 준비·메싱·덱·솔버·필수 후처리·기본 결과 생성까지의 경과 시간.
- 대기 시간: 앞선 작업 때문에 시작하지 못한 시간. 별도 표시.
- 초기 업로드/가져오기: 별도 측정하되 사용자 전체 소요 시간에서 숨기지 않음.
- 불필요한 고해상도 추가 내보내기는 별도 작업으로 표시.

추정값에는 기준 하드웨어, 스레드, 근거 케이스/모델 버전, 범위, 추정 시각을 저장합니다. 입력 변경으로 무효화된 추정값을 계속 실행 버튼 옆에 남기지 않습니다.

### 8.2 30분 초과의 처리

예상 범위 상한이 30분을 넘으면 경고를 표시합니다. “예상 28–38분으로 기본 시간 목표를 넘길 수 있습니다.”를 사용합니다. 기본 행동은 `30분 목표 설정 보기`이며, 무엇을 바꾸고 검증 범위가 어떻게 달라지는지 제시합니다.

사용자가 명시적으로 긴 실행을 선택할 수 있는 제품 정책이라면 고급 실행으로 분리하고 기록합니다. 시간만 맞추기 위해 검증되지 않은 과도한 조대화·물리 조건 변경을 자동 적용하지 않습니다. 해석 시간이 30분을 넘었다는 이유만으로 솔버를 갑자기 종료하지 않습니다. 자동 시간 제한이 있다면 실행 전에 정책을 표시해야 합니다.

### 8.3 사전 검사 결과

| 등급 | 예 | UI와 실행 |
|---|---|---|
| 차단 | 필수 재료 없음, 유효하지 않은 형상, 연결 불성립, 질량 오차 초과, 잘못된 수치 | 실행 불가. 문제 위치와 수정 버튼 |
| 검토 필요 | 미검증 재료, 검증 범위 밖, 시간 초과 예상 | 근거·영향 표시. 서버 정책이 허용할 때 실행 가능 |
| 정보 | 자동 적용된 메쉬·램프, 비교 기준 | 기본 설정 근거에서 열람 |

최종 게이트 중 실행 이후에만 알 수 있는 항목은 사전 통과처럼 표시하지 않습니다. 사전 검사는 스냅샷 해시와 연결합니다. 버튼 클릭 시 서버가 같은 입력인지 재검증하고, 변경됐으면 새 검사 결과를 반환합니다.

## 9. 실행 중·취소·복구

### 9.1 상태 모델

`draft → validating → ready → queued → running → completed`가 정상 흐름입니다. 실패·취소·중단은 별도 종결 상태입니다. `completed`는 계산 완료만 뜻하며 결과의 유효성과 설계 목표 충족은 별개입니다.

| 상태 | 화면 문구 | 주요 행동 |
|---|---|---|
| validating | “실행 조건을 확인하고 있습니다” | 입력 보기, 검사 취소 |
| queued | “대기 2번째 · 앞선 해석 1건” | 대기열에서 제거 |
| running | “메쉬 생성 중” / “해석 중” 등 실제 단계 | 진행 보기, 중단 |
| cancelling | “중단 요청을 처리하고 있습니다” | 중복 중단 방지 |
| completed | “계산 완료” + 별도 유효성 표시 | 결과 보기, 비교 |
| failed | 원인 한 문장 + 다음 행동 | 문제 위치, 진단 로그, 조건 복제 |
| cancelled | “사용자가 중단했습니다” | 새 실행으로 다시 시작 |
| interrupted | “실행 환경 중단으로 완료되지 않았습니다” | 상태 확인, 새 실행 |

진행 단계명은 실제 파이프라인과 매핑하고, UI에서 가상의 진행 단계를 추가하지 않습니다. 전체 %와 솔버 내부 %를 구분합니다. 솔버 50%가 전체 시간 50%를 뜻하지 않습니다.

### 9.2 갱신과 연결 끊김

실행 상태는 SPEC에 따라 5초 주기로 갱신합니다. 요청이 끝나기 전에 같은 요청을 중첩하지 않습니다. 실패 시 마지막 성공 시각과 `연결 확인 중`을 표시합니다. 클라이언트의 통신 실패를 솔버 실패로 변경하지 않습니다.

탭을 닫아도 서버 작업은 유지됩니다. 다시 열면 실행 ID로 상태를 복구합니다. 서버 재시작 시 실제 프로세스·산출물과 기록을 대조하고, 재개를 지원하지 않으면 `중단됨`으로 표시합니다. 로그 파일이 존재한다는 이유로 `실행 중`을 복원하지 않습니다.

### 9.3 불변 실행

제출 순간 형상 asset, 재료 카드 버전, 그래프 개정, 정규화한 케이스, 설정·솔버 버전을 동결합니다. 편집본은 계속 수정할 수 있지만 기존 대기·실행·완료 결과를 변경하지 않습니다.

버튼 연타·통신 재시도로 중복 작업이 생기지 않도록 제출 요청에 idempotency key를 사용합니다. 작업은 서버에서 직렬화합니다. 브라우저마다 별도 솔버를 동시에 시작하게 하면 안 됩니다.

대기 취소는 즉시 제거하고 알림을 표시합니다. 실행 중단은 “현재 계산은 중단되며 완료 결과가 생성되지 않을 수 있습니다”를 보여주는 한 번의 확인을 둡니다. 중단 완료 전에 ‘취소됨’을 확정하지 않습니다. 부분 결과가 있으면 `부분 결과 · 판정 불가`로만 제공합니다.

## 10. 결과를 읽고 판단하는 방식

### 10.1 결과의 첫 화면

상단 순서는 고정합니다.

1. 검토 이름, 실행 시각, 변경 파라미터.
2. **설계 질문에 대한 한 문장 답.**
3. 서로 독립된 `목표 판정`과 `결과 신뢰 정보`.
4. 핵심 지표 최대 3개.
5. 3D 변형·개방과 곡선.
6. `조건 하나 바꿔 비교`, `검증 근거`, `내보내기`.

| 상황 | 판단 문장 예 |
|---|---|
| 벤트 목표 내 | “개방 압력은 0.385 MPa로, 목표 0.30–0.50 MPa 안에 있습니다.” |
| 상한 초과 | “개방 압력은 0.56 MPa로, 목표 상한보다 0.06 MPa 높습니다.” |
| 가압 범위에서 미개방 | “최대 가압 압력 0.50 MPa까지 개방 기준에 도달하지 않았습니다.” |
| 목표 미입력 | “개방 압력은 0.385 MPa입니다. 목표 범위를 입력하면 비교할 수 있습니다.” |
| 모델 유효성 실패 | “모델 연결 검사가 실패하여 설계 판단에 사용할 수 없습니다.” |
| 재료 미검증 | “계산상 개방 압력은 0.385 MPa입니다. 재료 모델이 검증되지 않아 참고용으로 표시합니다.” |

위 수치는 문구 예시입니다. 미개방을 `개방 압력 0`으로 표현하지 않습니다. 최대 가압 압력보다 큰 실제 개방 압력을 추정해 만들어내지 않습니다.

### 10.2 목표와 신뢰를 분리

| 축 | 상태 |
|---|---|
| 설계 목표 | 목표 범위 내 / 하한 미달 / 상한 초과 / 목표 없음 / 판정 불가 |
| 계산 유효성 | 유효 / 무효 / 확인 불가 |
| 검증 근거 | 검증 범위 내 / 일부 조건 미검증 / 검증 범위 밖 / 근거 없음 |
| 진단 | 비치명 경고 수와 상세 원인 |

신뢰 수준은 백엔드 정책이 산출합니다. 프런트엔드가 에너지 오류 하나만 보고 전체 결과를 `신뢰도 높음`으로 바꾸면 안 됩니다. 비치명 게이트 근소 미달은 결과와 함께 표시하며, 모델 자체가 틀린 결과는 강조 수치와 목표 통과 표시를 억제합니다.

정밀 메쉬 대비 5% 차이와 실측 실험 대비 오차는 다른 근거입니다. 결과 근거에는 비교 대상·지표·조건·날짜·오차 정의를 적습니다. 검증 근거 없는 오차 막대나 ±10% 음영을 곡선에 그리지 않습니다.

### 10.3 3D 뷰어

- 처음 열면 전체 형상과 관심 부위가 보이는 카메라를 사용합니다. 자동 재생은 하지 않습니다.
- 재생/일시정지, 이전·다음 프레임, 처음, 속도, 시간 슬라이더를 제공합니다.
- 기본 변형 배율은 1×입니다. 확대 변형을 지원하면 화면에 `변형 5×`를 지속 표시합니다.
- 원본 윤곽 표시, 부품 숨김/표시, 캔·캡·벤트·스코어 범례, 선택 부품 보기 제공.
- 스코어는 확대해도 식별 가능하게 하되 색만으로 정상·파단을 구분하지 않습니다.
- 이벤트 클릭 시 대응 프레임과 곡선 위치를 함께 이동합니다.
- 저장 프레임이 성긴 경우 프레임 간 시각적 보간과 실제 계산 샘플을 구분합니다. 보간으로 파단 시각·지표를 새로 산출하지 않습니다.
- 내보낸 뷰어에는 입력 주요 치수, 단위, 실행 ID, 판단·신뢰 정보가 남아야 합니다.

WebGL을 사용할 수 없으면 정적 프레임 또는 서버 생성 영상, 핵심 지표, 곡선, 리포트 링크를 제공합니다. 빈 검은 화면으로 끝내지 않습니다. 독립 HTML은 서버 연결 없이 열려야 하며 **16 MB 이하**를 확인합니다. 용량 때문에 표시 프레임을 줄이더라도 지표·원시 곡선 데이터는 무단 변경하지 않습니다.

### 10.4 곡선과 수치

| 해석 | 기본 곡선 | 이벤트·보조 정보 |
|---|---|---|
| 압착·압궤 | 하중–변위 | 피크, 지정 변위, 평균 구간, 흡수 에너지 구간 |
| 벤트 | 압력–시간, 개방 면적–시간 | 초기 파단, 정의된 개방, 최대 가압 |

곡선은 축 이름·단위·범례·현재 샘플 값을 제공합니다. 원시 데이터가 있으면 CSV 내보내기를 제공합니다. 표시용 다운샘플링은 극값·이벤트를 보존하며 실제 지표 계산을 브라우저의 다운샘플 데이터로 다시 하지 않습니다.

수치적 가속을 사용한 솔버 시간은 실제 시험 시간과 구분합니다. 기본 화면에서 오해 가능성이 높으면 압력·변위 기반 이벤트를 우선하고 시간축에 `해석 시간`을 명시합니다.

초기 표시 정밀도는 유효숫자 약 3자리로 통일하되 작은 잔여 두께 등 설계 입력 구분에 필요한 자릿수를 보존합니다. 내부 원값을 반올림해서 저장하지 않습니다. 목표 경계 판정은 원값으로 수행하고 경계 근처의 반올림 혼동에는 상세값을 제공합니다.

### 10.5 A/B 비교

결과 목록에서 최대 두 개를 선택하는 것을 기본으로 합니다. 필요 시 최대 네 곡선까지 확장하되 기본 화면은 두 안의 이해에 최적화합니다.

- 좌측 또는 위에 기준 A, 우측 또는 아래에 변경안 B를 일관되게 배치합니다.
- 상단에 변경 조건만 비교하는 표를 제공합니다.
- 같은 물리량·단위·정의의 곡선만 중첩하고 같은 축 범위를 사용합니다.
- 재료·지지 조건·목표 정의까지 달라지면 차이를 전부 표시하고 단일 원인 효과로 표현하지 않습니다.
- 상대 차이는 `(B−A)/A`이며 기준값이 0이거나 결측이면 상대 % 대신 절대 차이를 표시합니다.
- 뷰어 동기화는 동일한 축 변수와 공통 범위에서만 사용합니다. 길이가 다른 결과를 강제로 늘려 맞추지 않습니다.
- ‘최적안’ 자동 선정은 최초 버전에 넣지 않습니다. 지표별 장단점과 목표 충족을 보여줍니다.

## 11. 리포트와 내보내기

리포트는 요약을 반복하는 장식 페이지가 아니라 결과의 근거를 보존하는 문서입니다.

필수 순서: 판단 요약 → 입력·가정 → 형상 처리 → 재료 → 메쉬·수치 조건 → 진단·게이트 → 검증 범위 → 지표·곡선 → 산출물.

| 항목 | 필수 기록 |
|---|---|
| 형상 | 원본 파일 표시명, asset 해시, 단위, 해석용 변환·단순화 |
| 조건 | 하중·지지·연결·설계 목표, 직접 입력과 기본값 출처 |
| 재료 | 카드 ID·버전·출처·검증 상태 |
| 수치 설정 | 메쉬 영역별 크기, 자동 정책 버전, 솔버 버전, 4코어 설정, 가속 관련 정보 |
| 시간 | 준비·솔버·후처리·총 실행·대기 시간, 추정과 실측의 차이 |
| 판정 | 지표 정의·단위·원값, 목표, 유효성, 검증 범위, 진단 |
| 재현 | 실행 ID, 입력 스냅샷 해시, 그래프 개정 |

내보내기 버튼은 실제 산출물의 준비 여부에 따라 활성화합니다. 기본 목록은 독립 뷰어 HTML, 리포트 HTML, 곡선 CSV, 지원되는 변형 STEP입니다. PDF나 임의 프레임 STEP이 구현되지 않았다면 존재하는 것처럼 제공하지 않습니다. STEP 내보내기에는 대상 부품·프레임·변형 배율 적용 여부를 명시합니다.

## 12. 시각 체계와 컴포넌트

### 12.1 디자인 방향

밝은 중성 배경, 선명한 타이포그래피, 얇은 구분선, 절제된 강조색을 사용합니다. 유려함은 카드 장식보다 정렬, 여백, 단계 간 연결, 형상과 데이터의 동기화에서 만듭니다. 기존 `doroper98/can_crush_sim`의 레이아웃·토큰·자산을 가져오지 않습니다. 뉴모피즘, 유리 효과, 과한 그라데이션, 움직이는 장식은 사용하지 않습니다.

| 대화상자 | 제목, 필요한 설명, 명확한 취소/실행. 닫힌 뒤 원래 포커스 복원 |

### 12.4 접근성과 조작

일반 텍스트 대비는 4.5:1 이상, 큰 텍스트는 3:1 이상을 기준으로 합니다. 터치 주요 조작은 제품 기준 44 × 44 CSS px 이상을 권고합니다. 이는 WCAG 2.2 AA의 최소 타깃 24 × 24 px 규정과 동일한 수치가 아닙니다. [W3C 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C 타깃 크기 설명](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

- 모든 입력에 실제 label, 모든 아이콘 버튼에 접근 가능한 이름을 둡니다.
- 포커스는 2 px 이상 외곽선과 여백으로 보이며 고정 실행 바에 가려지지 않습니다.
- 그래프에는 키보드로 읽고 편집할 수 있는 노드 목록과 연결 메뉴를 제공합니다.
- 오류 메시지는 색 외에 아이콘·문자를 포함하고 해당 입력과 연결합니다.
- 5초 폴링의 모든 수치를 읽어 주지 않습니다. 상태 전환과 실패·완료만 적절히 알립니다.
- 재생은 자동 시작하지 않으며 동작 감소 설정에서는 장식 전환을 제거합니다.
- 모바일: 한 손가락 회전, 두 손가락 이동·핀치 확대와 동등한 버튼 조작을 제공합니다. 조작 규칙은 첫 뷰어 진입 시 짧게 안내합니다.
- 200% 확대에서 필드와 버튼이 겹치지 않아야 합니다. 그래프·3D 공간 자체의 이동과 문서 읽기의 가로 스크롤은 구분합니다.

## 13. 프런트엔드 구조

기존 `crushsim/ui/static/index.html` 안에서 의존성 없는 HTML/CSS/JavaScript로 구현합니다. React, React Flow, 번들러, 외부 CDN을 전제로 한 설계로 바꾸지 않습니다. 그래프는 DOM 노드와 SVG 연결선으로 구현할 수 있습니다. 기존 뷰어 기술을 재사용하고 브라우저에 물리 계산이나 바이너리 결과 파서를 새로 만들지 않습니다.

코드가 단일 파일이라는 이유로 상태를 전역 변수에 무작위로 흩어 놓지 않습니다. 아래 책임을 함수/객체 단위로 구분합니다.

| 책임 | 역할 |
|---|---|
| AppState | 편집본·선택·현재 단계·실행 참조 |
| ApiClient | 요청, 오류 정규화, 중복 요청 방지 |
| CapabilityRegistry | 지원 목적·템플릿·필드·제약 |
| GraphModel | 노드·연결·개정·명령 기반 undo/redo |
| GuidedSetup | 동일 GraphModel을 설계 언어로 편집 |
| GraphView / Inspector | 상태의 표시와 사용자 명령 전달 |
| RunStore | 서버 실행 상태와 편집본의 분리 |
| ResultPresenter | 서버 지표·정의에 따른 문구·표시 단위 |

프런트엔드는 빠른 필드 검증과 그래프 미리보기를 담당합니다. 최종 케이스 정규화, 지원 여부, 물리 검증, 시간 추정, 실행 스냅샷은 서버가 책임집니다. 현재 브라우저 컴파일러는 호환 경로로 유지할 수 있지만 서버 검증을 통과한 입력만 실행합니다.

## 14. API 변경안과 데이터 계약

### 14.1 기존 API 재사용

| 기존 경로 | 유지할 기능 | 보완 사항 |
|---|---|---|
| `GET /api/cases` | 기존 케이스 목록 | 표시명·지원 목적·오류의 사용자 문구 |
| `GET /api/cases/{file}/raw` | 기존 케이스 가져오기 | 그래프 변환 시 누락 필드 보고 |
| `PUT /api/cases/{file}` | 케이스 저장 | 실행 스냅샷과 분리 |
| `GET /api/graphs`, `GET/PUT /api/graphs/{name}` | 그래프 저장·열기 | 버전·개정 충돌·원본 보존 |
| `GET /api/runs` | 실행 목록 | 안정된 run ID와 통합 상태·진단 |
| `POST/DELETE /api/runs/{case_file}` | 기존 실행·취소 호환 | 내부에서 스냅샷 실행으로 연결 |
| `GET /api/runs/{name}/viewer`, `/report`, `/step` | 산출물 | 준비 상태·버전·대상 정보 |

### 14.2 제안 API

아래 경로는 **신규 제안**입니다. 기존 동적 경로와 충돌하지 않도록 신규 실행 자원은 `/api/executions`로 분리했습니다. 실제 구현에서 동일 계약을 만족하는 다른 경로를 선택할 수 있습니다.

| 경로 | 요청·응답의 핵심 |
|---|---|
| `GET /api/capabilities` | 지원 목적·템플릿 버전, 업로드 제한, 실행 가능 상태, 기능 플래그 |
| `POST /api/assets` | 파일 업로드 → asset ID·가져오기 작업 ID |
| `GET /api/assets/{id}` | 준비 상태, 미리보기 참조, 단위·치수·부품, 추출 진단 |
| `POST /api/preflights` | 그래프 개정+asset 참조 → 정규화 입력 해시·검사·예상 시간·조합표 |
| `POST /api/executions` | preflight ID+입력 해시+idempotency key → 불변 실행 ID와 대기 상태 |
| `GET /api/executions/{id}` | 상태·단계·시간·진단·스냅샷 참조 |
| `POST /api/executions/{id}/cancel` | 취소 요청 → 실제 상태 확인까지 cancelling |
| `GET /api/executions/{id}/result` | 지표 정의·단위·목표·유효성·검증 근거·곡선/산출물 참조 |

긴 형상 처리는 비동기 작업으로 응답하고 상태를 조회합니다. 파일 바이트와 전체 메쉬를 5초마다 다시 전송하지 않습니다. 미리보기는 서버가 생성한 표시용 데이터이며 원본 STEP과 구별합니다.

### 14.3 최소 데이터 계약

| 객체 | 필수 필드 |
|---|---|
| Capability | schema_version, analysis_type, available, unavailable_reason, template_id/version, supported_geometry |
| Asset | id, content_hash, display_name, status, units, dimensions, parts, diagnostics |
| GraphDraft | schema_version, revision, nodes, edges, asset_refs, template_ref, targets |
| Preflight | id, input_hash, checks, runnable, estimate, combinations, policy_version |
| Execution | id, snapshot_hash, state, stage, timestamps, queue_position, diagnostics, artifacts |
| Metric | key, value/null, unit, definition_id/version, evaluation_range, unavailable_reason |
| Validation | model_validity, scope_status, references, diagnostics, policy_version |

아래 JSON은 신규 결과 계약의 형식 예시이며 계산 실적이 아닙니다.

### 14.4 오류 계약

오류에는 안정된 `code`, 사용자용 `message`, `severity`, `field_path` 또는 `node_id`, 가능한 `actions`, 진단용 `detail`을 둡니다. 영어 예외 문자열만 UI에 그대로 노출하지 않습니다.

예시 코드: `ASSET_UNSUPPORTED`, `UNIT_CONFIRMATION_REQUIRED`, `MODEL_DISCONNECTED`, `MASS_MISMATCH`, `MATERIAL_NOT_VALIDATED`, `TIME_BUDGET_EXCEEDED`, `STALE_PREFLIGHT`, `REVISION_CONFLICT`.

코드 이름은 제안이며 기존 예외와 매핑해야 합니다. 게이트 임계값을 CSS/JS에 복제하지 않습니다. 백엔드가 원인·심각도·실행 가능 여부를 결정하고 UI는 일관되게 전달합니다.

## 15. 성능·파일 처리 원칙

- 초기 작업 화면은 SPEC의 2초 목표를 따릅니다. 대형 형상 로딩 완료와 첫 화면 준비를 별도로 계측합니다.
- 클릭·선택·패널 열기는 100 ms 내 가시적 반응을 목표로 합니다. 서버 작업의 완료 시간을 이 수치와 혼동하지 않습니다.
- 입력마다 서버에서 전체 메쉬를 재생성하지 않습니다. 편집 중 표시용 미리보기와 실행 전 정밀 준비를 구분합니다.
- 대형 형상 미리보기는 표시용 경량화 수준을 표시하고 원본 정확도와 구별합니다.
- 사용자 파일명·부품명·로그는 HTML로 삽입하지 말고 텍스트로 처리합니다.
- 파일은 서버가 생성한 ID에 매핑하고 사용자가 임의 파일 경로를 업로드 이름으로 지정하지 못하게 합니다.
- 업로드 크기·유형·파싱 실패를 서버에서 검증합니다. 임시 자산과 실패 작업의 정리 정책을 둡니다.
- 기본 로컬 사용에서 외부 폰트·CDN·분석 서비스에 의존하지 않습니다.
- 독립 뷰어는 상대 API 호출 없이 필요한 표시 데이터를 포함합니다. 서버에서 열었을 때만 동작하는 파일을 ‘독립 HTML’로 부르지 않습니다.

## 16. 구현 순서와 완료 산출물

### P0. 입력과 실행의 신뢰 기반

대상: `server.py`, 기존 케이스·그래프 변환 경로, 실행 메타데이터.

산출물: capability, STEP 업로드/가져오기, 서버 사전 검사, 불변 실행, 중복 제출 방지, 안정된 오류 계약. UI가 지원하지 않는 기능을 실행 가능으로 표시하지 않아야 합니다. 그래프 파일의 기존 round-trip을 보존합니다.

### P1. 첫 실행 작업실

대상: `static/index.html`.

산출물: 새 시작 화면, 네 단계 안내, 형상/그래프 분할, 속성 패널, 목적 템플릿, 시각적 하중·고정, 예상 시간, 같은 화면의 실행 패널. 기존 Submit/Monitor 동작을 통합하고 기존 케이스를 열어도 같은 편집 모델을 사용합니다.

### P2. 판단 가능한 결과

대상: `viewergen.py`, `static/viewer_template.html`, 결과 메타데이터·리포트 생성 경로.

산출물: 판단 문장, 목표와 신뢰 분리, 이벤트와 곡선 동기화, A/B 중첩, 조건 차이표, 모바일 조작, 독립 HTML 16 MB 검사. 예전 결과에 새 메타데이터가 없으면 `정보 없음`으로 표시하고 임의 복원하지 않습니다.

### P3. 그래프 생산성과 확장

산출물: 키보드 연결 편집, undo/redo, 개정 충돌, 조합 미리보기, 고급 설정, 추가 지원 템플릿. 전기·열 해석은 별도 백엔드 검증 후 capability로 활성화합니다.

각 단계는 실제 지원 사례의 세로 흐름 하나를 끝까지 연결한 후 확장합니다. 화면을 모두 만든 뒤 마지막에 물리 파이프라인을 연결하는 방식은 피합니다. 첫 대표 흐름은 **각형 캔 벤트 템플릿 → 제출 → 개방 지표 확인 → 잔여 두께 하나 변경 → 비교**입니다. STEP 흐름도 별도의 대표 지원 파일로 같은 전체 경로를 검수합니다.

## 19. 사용성 검증과 SPEC 추적

### 19.1 첫 사용자 시험

해석 전문가가 아닌 셀 설계자 최소 5명을 대상으로 진행하는 것을 권고합니다. 샘플은 대표 지원 STEP, 기본 각형 벤트 템플릿, 일부 정보가 빠진 STEP을 준비합니다. 전문가가 옆에서 답을 알려주지 않습니다.

과업은 ① 첫 제출 ② 고정 방향 확인 ③ 잔여 두께 변경 비교 ④ 결과가 목표 범위인지 설명 ⑤ 미검증 재료 결과의 한계를 설명하기입니다.

측정 항목: 시작부터 제출까지 시간, 파일 처리 시간, 첫 시도 성공, 잘못 확정한 필수 조건, 도움 요청, 결과 해석 오류, 비교 완료 시간. 5명 중 4명 이상이 대표 기본 사례를 3분 안에 올바르게 제출하는 것을 초기 출시 기준으로 권고합니다. 잘못된 조건으로 빨리 제출한 사례는 성공에 포함하지 않습니다. 이는 제안 기준이며 측정 실적이 아닙니다.

## 20. 구현 착수 지침

첫 구현에서는 다음 연결을 완성합니다: **지원 STEP 또는 각형 템플릿 → 목적 선택 → 필수 조건 확인 → 사전 검사·예상 시간 → 불변 실행 → 판단 문장이 있는 결과 → 한 조건 변경 비교**.

화면의 모든 활성 버튼은 실제 백엔드 기능에 연결하고, 준비되지 않은 기능은 capability로 구분합니다. 형상·설계 입력·그래프·케이스·실행 스냅샷 사이에 중복된 진실을 만들지 않습니다. 실제 해석 조건을 바꾸는 자동화는 그 근거와 적용 범위를 남깁니다.

완료 검토에서는 예쁜 화면의 유무보다 **첫 사용자가 올바른 문제를 빠르게 제출하고, 결과의 방향과 한계를 스스로 설명할 수 있는가**를 확인합니다.
