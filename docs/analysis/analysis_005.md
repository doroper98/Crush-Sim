## 1. LC-6 총 회전 시간 — 우리가 astra에게 준 숫자가 틀렸다

003 §8에 "0.5 mm ≈ 25분"이라 썼다. `pipeline_summary.json`과 엔진 `.out`을 다시
읽으니 틀렸다.

| 스코어 메쉬 | 케이스 | 사이클 | 엔진 시간 | 개시 / 개방 MPa | 0.3 mm 대비 |
|---|---|---|---|---|---|
| 1.2 mm (균일) | v5 | 76,549 | 665 s (**11분**) | 0.514 / 0.703 | +79 % / +92 % |
| 0.5 mm | v5_medium | 243,747 | 2,361 s (**39분**) | 0.303 / 0.385 | +6 % / +5 % |
| 0.3 mm | v5_fine | 2,445,570 | 26,314 s (**7.3시간**) | 0.287 / 0.366 | 기준 |

스타터는 각 1~4초, 메싱·덱·후처리는 합쳐 1~2분이다(뷰어 생성 제외). 즉 사용자
관점 총 시간은 엔진 시간 + 약 2분.

결론: **두 숫자(≤30분, ≤10%)를 동시에 만족하는 LC-6 프리셋이 아직 없다.** 0.5 mm는
정확도는 맞지만 예산을 9분 넘고, 1.2 mm는 예산 안이지만 정확도가 두 배 가까이
틀린다. 004 §0의 "0.5 mm를 기본으로 받아들인다"는 틀린 입력 위의 결론이었다.

→ **예산 메쉬 탐색 실행 중**: `lc6_pris_vent_burst_v5_budget` (스코어 0.65 mm).
0.7 mm를 먼저 시도했다가 메쉬 게이트에 거부됐다 — 최소 변 0.218 mm < 한계
`vent_size/3` = 0.233 mm. 가장 짧은 변은 스코어 호 임프린트에서 나오고 vent_size와
무관하게 0.21 mm 근처라(0.5 mm 케이스 0.208), 세분용으로 만든 `vent_size/3` 가드가
**성기게 할 때** 문다. 0.65 mm(한계 0.217)로 우회했고, 가드 규칙 자체는 이
문서의 결론을 보고 정한다. 결과는 §1.1에 채운다.

### 1.1 예산 메쉬 결과 — 메쉬가 아니라 종료 시점이 예산을 지배한다

| 런 | 스코어 메쉬 | 종료 | 사이클 | 엔진 | 총 벽시계 | 개시 / 개방 MPa | 0.3 mm 대비 | 에너지 오차 |
|---|---|---|---|---|---|---|---|---|
| v5_medium | 0.5 mm | 3.5 ms | 243,747 | 39.4분 | ~41분 | 0.303 / 0.385 | +5.7 % / +5.3 % | 9.1 % |
| v5_budget | 0.65 mm | 3.5 ms | 282,200 | **46.8분** | ~48분 | 0.314 / 0.389 | +9.3 % / +6.4 % | 12.7 % |
| **v5_preset** | **0.5 mm** | **1.8 ms** | 87,491 | **13.6분** | **14.4분** | **0.303 / 0.385** | **+5.7 % / +5.3 %** | 6.7 % |

읽는 법:

- **0.65 mm는 0.5 mm보다 오히려 느렸다**(47 vs 39분). 요소는 줄었지만 파단
  이후 시간 간격이 무너지는 구간이 비용을 지배해서, vent_size로는 예산을
  살 수 없다. 004 §2.2 "최소 변만으로 실행 시간을 예측하면 부족하다"의 실증.
- 0.65 mm 런의 진행 기록: 1.5 ms까지 7분, 그 뒤 2 ms에 40분. 램프가
  0.85 MPa / 3 ms라 개시(0.30 MPa)는 1.1 ms, 개방(0.385)은 1.4 ms에 온다. 앞단
  사용자가 필요한 것은 거기까지다(004 §2.3 1항 "필요한 출력까지만 계산").
- **프리셋 = 0.5 mm + `solver.end_time: 1.8e-3`**. 램프 테이블은 그대로 두고
  엔진만 자른다(writer 확인). 결과는 medium과 소수 넷째 자리까지 같다 — 같은
  모델의 같은 1.36 ms이니 당연하고, 그것이 곧 "개방 이후는 계산할 필요 없다"의
  증거다. 총 14.4분, 10 % 안. **이 저장소의 첫 30분·10% 프리셋이다.**
- 에너지 오차 6.7 %는 여전히 5 % 게이트 밖이다(요소 삭제가 내부에너지를
  수지에서 뺀다, `VENT_BURST.md`). §4 표대로 "경향 참고" 등급 후보.
- 컨테이너 4코어 기준이다. 004 §0의 지적대로 기준 노트북에서 한 번 교정해야
  한다(사용자 몫, §6 Q5).

004 §5.1 "이미 확보한 fine 결과는 재사용한다"에 따라 0.3 mm는 다시 돌리지
않았다. 개방 이후를 잘라도 되는지는 다른 출력(개구 면적-시간 곡선 전체)이
필요한 순간 다시 판단한다 — 그때는 다른 프리셋이다(004 §2.3).

004 §2.1의 "임의 역산이 아니라 검증된 설정 목록에서 선택"에 동의한다. 이 실험이
바로 그 목록의 첫 항목을 만드는 일이다. 004 §2.2의 지적대로 초반 사이클 속도로
ETA를 내지 않고 완주 시간으로 기록한다.

## 2. Honda/cylin 질량 오차의 단계별 분해 — 004 Q1이 요구한 표

004는 "−7~−8%를 chord 손실로 설명할 수 없다(R23·1.5 mm에서 0.018%)"고 했다. 맞다.
004가 요구한 면적 이력을 계산했다(균일 두께 t = 케이스 두께, V = 원본 솔리드 체적).

| 단계 | cylin (t 0.4, V 6,646) | 오차 | Honda (t 0.38, V 7,447) | 오차 |
|---|---|---|---|---|
| A0 광선 판정이 "외피"로 고른 면 | 7면 16,736 | **+0.7 %** | 27면 19,496 | **−0.5 %** |
| A1 봉합 후 최대 쉘 | 6면 15,305 | −7.9 % | 18면 18,326 | −6.5 % |
| A1′ healShapes 후 | 6면 15,305 | −7.9 % | 18면 18,326 | −6.5 % |
| A2 띠 면 디피처링 후 | 5면 15,248 | −8.2 % | 17면 18,228 | −7.0 % |
| Ah 메싱(목표 1.5 mm) | 4,695 요소 15,212 | −8.4 % | 7,615 요소 18,162 | −7.3 % |

읽는 법:

- **메싱(A2→Ah)은 0.2~0.3 %**. 004 말대로 chord 손실은 무시할 크기다. 003 §2.1에서
  내가 "(c) chord 손실이 더 크다"고 쓴 것은 틀렸다.
- **디피처링(A1→A2)은 0.3~0.5 %**. 림 띠 한 면.
- **A0→A1의 7~8 %가 전부다.** 봉합 후 최대 쉘만 남기며 버린 것: cylin은 1,431 mm²
  면 하나(봉합에 붙지 않은 자유 면), Honda는 쉘 셋(3.5 + 3.5 + 1,163 mm²).

그러면 버린 게 진짜 외피였나? **아니다.** 위치를 보면:

| 파일 | 버린 조각 | bbox | 정체 |
|---|---|---|---|
| cylin | 1,431 mm² | — | π(22.6−1.3)² = 1,425 → **안쪽 바닥 평면** |
| Honda | 1,163 mm² 3면 | y ±4.9 (벽은 ±6.28), z −64.3~−63.3 | **안쪽 바닥 + 필렛** |
| Honda | 3.5 mm² ×2 | 캡 시트 스텝 | 안쪽 단차 |

즉 004 §3.1·Q2가 예측한 **"열린 컵의 안쪽 면에서 입구로 나가는 광선은 아무것도
만나지 않아 외피로 오분류된다"** 가 두 캔 모두에서 실제로 일어났다. 둘 다 위가
열린 캔이고, 안쪽 바닥에서 위로 쏜 광선이 입구로 빠져나간다. "최대 쉘만 유지"
규칙(EXP-005)이 그것을 정확히 걸러냈다 — 우연히 맞은 것이지만 맞았다.

그러면 −7~−8 %는 어디서 오나? **바닥이 벽보다 두껍다.** 요소별 광선 게이지의
분포:

| | 벽 (p50) | 바닥 | 근거 |
|---|---|---|---|
| cylin | 0.382 | **0.80** | z=0 요소 728개 전부 0.8 |
| Honda | 0.38 | **0.70** | z −65~−64.25 요소 601개 |

단일 두께 0.4/0.38로 바닥 면적(cylin 1,662 mm²)을 곱하면 바닥 질량의 절반을
잃는다: cylin 1,662 × 0.4 = 665 vs 실제 ≈ 1,330 → 체적의 10 %. 이것이 −8 %다.
A0가 "0 %"였던 것은 **잘못 포함된 안쪽 바닥 면적이 두꺼운 바닥의 결손을 우연히
메운 것**이다. 004 §2.3(질량 일치 ≠ 이상화 OK)의 살아 있는 예.

### 2.1 그래서 요소별 두께를 STEP 경로에 넣으면 되는가 — 아직 아니다

`gauge_elements`를 메싱된 외피에 그대로 돌려 봤다:

| | 단일 두께 | 요소별 게이지 | 게이지 상태 |
|---|---|---|---|
| cylin | −8.4 % | **−45 %** | p10 = 0.022 mm (자기 면 재충돌), 이상치 필터 무력 |
| Honda | −7.3 % | −9.2 % | 7,615 중 **5,538개가 fallback**(광선 실패) |

004 §3.4가 지적한 그대로다: healShapes(0.5 mm)·스무딩을 거친 메쉬의 요소 중심은
원본 CAD 면 위에 있지 않고, 거기서 쏜 양방향 최근접 광선은 자기 면이나 허공을
잰다. EXP-004에서 이 함수가 통과한 것은 `can/test.stp`의 평면 위주 형상이었기
때문이다. → 요소별 두께를 STEP 경로에 넣으려면 **004 §3.4의 "원본 face에 투영 후
측정"이 선행**이다. 지금은 단일 두께 + 질량 게이트(−8 %, 한계 10 %)로 두되, **바닥
두께가 다른 캔은 게이트 여유가 2 %밖에 없다**는 것을 HANDOVER에 적는다.

### 2.2 이 결과가 004 T1에 주는 답

004 §1.2 "질량 + 30분만으로는 부족하다"에 **동의한다.** 위 표가 증거다 — A0는
질량 0 %인데 안쪽 면이 들어 있었다. 004가 든 네 조건 중 "의도한 벽 한 장"은 지금
"최대 쉘 유지"가, "자유 비행 조각 없음"은 연결성 게이트가 맡고, "보호 특징"과
"두께 범위"는 없다. 다만 앞단 목표에서 **지원 형상군을 "위가 열린/닫힌 캔 +
캡·벤트"로 선언**하면, 열린 컵 오분류는 "바닥 방향 광선의 재충돌 대상 = 캡
평면"으로 닫을 수 있다. 이것이 004 §3.2의 8단계보다 훨씬 싸고 우리 형상군에는
충분하다.

## 4. 게이트 분류 — 004 §3이 요구한 "정지 / 등급" 목록

현재 코드의 모든 판정을 004 §3.1의 세 등급으로 나눈 제안. **코드는 아직 바꾸지
않았다**(ADR-06 개정은 사용자 결정, §6 Q3).

| 판정 | 지금 | 제안 | 이유 |
|---|---|---|---|
| 이중 벽 / 안쪽 면 포함 (§2) | 최대 쉘 규칙 + 질량 게이트 | **정지** | 물리적으로 다른 모델 |
| 미연결 조각 (연결성) | 정지 (assembly만) | **정지**, step 경로에도 | 자유 비행체 |
| 질량 보존 ±10 % | 정지 | **정지** | 필요조건, 판별력 실증 |
| 케이스 두께 vs 게이지 벽 ±10 % | 정지 (이번에 추가) | **정지** | 덱이 CAD에 없는 벽을 갖는다 |
| 솔리드 2개 이상을 `kind: step`에 | 정지 | 정지 | 어셈블리 kind 없음 |
| 발산·NaN·질량 폭증 | 솔버 실패 | 정지 | — |
| min SICN ≥ 0.3, 종횡비 ≤ 5, 삼각형 ≤ 15 % | 정지(재메싱 3회 후) | **등급** — 경계 근처(SICN 0.25~0.3)는 "경향 참고", 그 아래는 정지 | 004 §3.2 "임의 경계선 근거 없음"에 동의 — 사례가 모이기 전까지 **현 한계 유지**, 등급 표시만 추가 |
| 최소 변 ≥ 0.3 mm (또는 vent_size/3) | 정지 | **예산 계산으로 대체** — 최소 변은 품질이 아니라 시간이다. 예상 시간 > 30분이면 경고 | §1의 0.7 mm 거부가 보여준 대로 이 가드는 목적과 어긋나게 동작한다 |
| 비다양체 변 = 0 | 정지 | 정지 (파트별), 선언된 용접선은 예외 | 004 §4.3 |
| 에너지 오차 ≤ 5 % | 정지 | **등급** — 요소 삭제 케이스(LC-6)는 "경향 참고", 급증·비정상 운동은 정지 | 004 §3.2 |
| hourglass/IE ≤ 10 %, KE/IE ≤ 5 % | 정지 | KE/IE 초과는 **정지** (EXP-005: 자유 비행체 신호), hourglass는 등급 | — |
| 부가질량 ≤ 2 % | 정지 | 등급 + 파트별 표시 | 004 §2.4: 포일에 집중되면 전체 2 % 안에서도 위험 |
| 재료 `verified: false` | 경고 문구 | **등급 "경향 참고"** | 이미 그렇게 쓰고 있다 |
| 벤트 개방 마일스톤 미도달 | 없음 | **"판정 미완료"** 별도 상태 | 004 §2.3: 30분 시점 미완료를 최종값으로 내보내지 말 것 |

004 §3.3의 "자동화 조건 = 선언 가능 + 재현 가능 + unknown 구별"에 동의한다. 위
표에서 "정지"는 그 세 조건을 이미 갖춘 것들이다.

## 5. 004 T6 — 기록 규약 채택

004 §7의 다섯 상태(구현됨 / 연결됨 / 검증됨 / 기본값 채택 / 폐기·인용 금지)를
받아들인다. `CLAUDE.md`에 "작업 시작 시 fetch → ahead/behind 기록 → 문서의
'완료'를 실제 호출 경로·테스트·런과 대조" 규칙을 넣는다(이 커밋). 이 문서 §1이
그 규칙의 첫 적용이다 — "0.5 mm ≈ 25분"은 문서에만 있고 런 기록과 대조되지
않았던 값이다.

## 6. 사용자가 답해야 004의 다음 판단이 가능한 것

004 §9 표의 두 항목은 저장소가 아니라 사용자의 도메인 지식이다.

- **Q1 (③ 저항)** 먼저 필요한 출력은 무엇인가 — (a) 전압 탭 사이 총 저항, (b)
  리벳 여러 개 사이의 전류 분배, (c) 접합부 국소 온도. 004는 (a)면 저항망으로
  충분하고 (b)(c)부터 FE가 필요하다고 본다.
- **Q2 (④ 열전파)** 보유한 데이터: 셀 열용량·이방성 전도도, 셀 간 접촉 열저항,
  SOC/화학계별 열폭주 열원과 방출 분율, 대표 전파 시험 결과. 없으면 004 §4.4대로
  "주어진 열원 시나리오에서 인접 셀 온도"까지만 제공 범위가 된다.
- **Q3 (게이트 정책)** §4 표의 "등급" 열을 채택할지. 채택하면 ADR-06 문구
  개정과 결과 화면의 등급 표시(SPEC §10.4)가 뒤따른다.
- **Q5 (기준 노트북)** 프리셋 14.4분은 4코어 컨테이너 값이다. 실제 기준 노트북
  (사양 명시)에서 `csim all --config configs/cases/lc6_pris_vent_burst_v5_preset.yaml`
  한 번의 총 시간이 있어야 30분 예산이 확정된다.
- **Q4 (지원 형상군)** 앞단 도구가 보장할 STEP 형상군을 "위가 열린/닫힌 원통·각형
  캔 + 판형 캡 + 포일 벤트"로 선언해도 되는가. §2.2의 값싼 오분류 방지책은 이
  선언 위에서만 성립한다.

## 7. 이 커밋에서 바꾼 것 / 안 바꾼 것

바꾼 것: 문서 정정(§1 시간), 예산·프리셋 케이스 추가와 실행(§1.1), `CLAUDE.md`
대조 규칙, `LOG.md` §12, `DEVLOG` EXP-007, HANDOVER §4에 "바닥 두께가 다른 캔은
질량 게이트 여유 2 %" 기록. 그리고 부수 발견 하나: **벤트 지표 캐시(`post.vent`)가
첫 `csim all`에서는 항상 비어 있었다** — `vent_metrics`가 아직 안 쓰인
`pipeline_summary.json`을 읽어야 했기 때문. 파이프라인이 덱 파트를 직접 넘기도록
고치고 테스트를 붙였다. UI 결과 노드가 새 런의 개방 압력을 못 보여주던 원인.

안 바꾼 것: 게이트 정책(§4 제안만), 요소별 게이지 투영(§2.1), 최소 변 가드,
열린 컵 시드 규칙(§2.2). 전부 §6의 답 또는 §1.1의 결과를 본 뒤.
