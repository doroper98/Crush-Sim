## 0. 먼저 답하면

가장 먼저 고칠 것은 메셔의 품질 수치가 아니라 **어느 물리적 벽을 어떤 한 장의 쉘로 표현하는지**다. 잘못 선택한 두 피부를 아무리 좋은 요소로 메싱해도 올바른 캔이 되지 않는다.

OCC의 offset·sewing이나 Gmsh의 `generate(2)` 하나로 임의의 얇은 솔리드를 견고하게 한 장으로 바꾸는 범용 해법은 없다. 이 프로젝트에서는 **원본 솔리드 보존 → 부품별 벽 두께/대향면 관계 분석 → 외피 선택 → 선택한 표면만 별도 모델로 메싱 → 두께·연결·접촉 검증**을 권한다. 판단이 모호한 구역은 설정으로 지정하거나 중단해야 한다.

| 질문 | 권고 | 제약과의 관계 |
|---|---|---|

## 1. 질문 문서와 현재 구현 사이의 차이

검토한 파일은 `CLAUDE.md`, `docs/HANDOVER.md`, `docs/LOG.md`, `docs/SPEC-v2.1.md`, 분석 인덱스 및 아래 관련 코드다. 질문의 일부는 현재 코드보다 이전 상태를 설명한다.

- [skin.py](../../crushsim/geometry/skin.py)에 이미 외피 추출, 두께 추정, 중립면 방향 절점 이동 함수가 있다.
- [assembly.py](../../crushsim/meshing/assembly.py)에 이미 솔리드별 외피 추출과 공통 토폴로지 메싱 경로가 있다.
- 그러나 일반 STEP 입력의 [pipeline.py](../../crushsim/pipeline.py)는 [mesher.py](../../crushsim/meshing/mesher.py)의 `mesh_step_surfaces()`를 호출한다. 이 경로에는 외피 추출이 통합되어 있지 않다. 함수가 존재하는 것과 실제 해석 경로가 사용하는 것은 다르다.
- `skin.py`의 절점 offset 함수도 외피 추출 시 자동으로 적용되는 것이 아니다. 따라서 모든 경로를 “중립면 메싱”이라고 부르면 안 된다.
- `LOG.md`의 일부 실험 성공과 미해결 기록은 범위가 다르다. 작은 어셈블리 실험의 성공을 15-solid `Honda_Cap_Assy.stp` 검증으로 확대할 수 없다.

아래 답변은 새 알고리즘 제안뿐 아니라 이 기존 구현의 취약점도 포함한다.

## 2. 먼저 바로잡아야 할 전제 네 가지

### 2.1 두 피부가 있으면 질량·막강성이 무조건 2배인가?

같은 면적을 가진 두 장에 각각 실제 두께와 같은 값을 주었을 때의 근사다. 질문의 예시는 CAD 두께와 덱 두께도 다르다. 끝단 띠·곡률·면적 차이를 무시하면 다음과 같다.

| CAD 벽 두께 | 두 피부 각각의 덱 두께 | 질량·막강성 비, `2 t_deck / t_CAD` |
|---|---|---|
| 0.40 mm | 0.30 mm | 1.50 |
| 0.38 mm | 0.30 mm | 약 1.58 |

굽힘은 연결 조건까지 알아야 한다. 서로 독립적인 두 평판의 국소 굽힘강성을 단순 합산하면 비율은 `2 t_deck³ / t_CAD³`이며 위 두 경우 약 0.844, 0.984다. 두 장이 떨어져 있다는 이유만으로 완전 합성단면의 큰 굽힘강성을 적용할 수는 없다. 전단 전달, 끝단 띠의 연결, 접촉과 경계조건이 실제 거동을 바꾼다.

따라서 기존 압착 곡선에 1/2 같은 계수를 곱해 보정해서는 안 된다. 올바른 외피·두께·접촉으로 다시 해석해야 한다. 위 계산은 오류의 성격을 설명하는 평판 근사이며 실제 캔 하중비 예측이 아니다.

### 2.2 0.4 mm 띠에는 최소 변 0.3 mm 요소가 들어갈 수 없는가?

그렇지 않다. 평평한 직사각형 띠에는 `0.4 × 1.2 mm` 사각형을 폭 방향 한 줄로 놓을 수 있다. 최소 변은 0.4 mm, 단순 길이비는 3이다. 실제 SICN과 종횡비는 구현된 지표로 평가해야 하지만, 폭 자체가 원리적 불가능 조건은 아니다.

실패 원인은 폭 방향 과분할, 모서리 분할 불일치, 곡률, 접합부 왜곡일 수 있다. `폭 < 2 × 최소변`은 **두 줄로 나누면 위험하다는 후보 조건**이지 삭제 조건이 아니다. 반대로 폭 0.1 mm를 실제 횡단 변으로 보존해야 한다면 0.3 mm 비용 가드와 충돌한다. 그때는 모델 단순화 또는 명시적인 비용 가드 예외가 필요하다.

### 2.3 질량 오차 ±10%는 이상화의 충분조건인가?

아니다. 잘못된 두 피부에 절반 두께를 주어 질량을 맞출 수도 있고, 작은 면적의 림·스코어를 지워도 전체 질량 변화는 작을 수 있다. 질량은 필요한 검사항목 중 하나다. 벽 중복, 보존 특징, 두께 분포, 용접 위치, 하중 경로와 접촉 간격을 별도로 검사해야 한다.

특히 `t = V / A_selected`로 두께를 추정한 뒤 같은 `A_selected × t`로 질량 일치를 평가하면 순환 검증이다. 독립적인 국소 두께 측정이나 명시된 공칭 두께와 비교해야 한다.

### 2.4 Ishell=24는 완전 적분 쉘인가?

[gates.py](../../crushsim/meshing/gates.py)의 설명은 수정 대상이다. 공식 문서에서 Ishell=24는 물리적 안정화를 사용하는 QEPH다. 면내 1점 적분과 두께 방향 적분점 수는 별개이며 `N=5`가 면내 완전 적분을 뜻하지 않는다. QEPH의 hourglass energy 출력 해석도 일반적인 감쇠형 hourglass 요소와 같다고 가정하면 안 된다. 저장소 고정 솔버 버전에서 실제 출력과 에너지 게이트 의미를 확인해야 한다. [공식 쉘 속성](https://help.altair.com/hwsolvers/rad/topics/solvers/rad/prop_type1_shell_starter_r.htm), [QEPH 이론](https://help.altair.com/hwsolvers/rad/topics/solvers/rad/theory_element_adv_elasto_plastic_hourglass_control_r.htm), [쉘 요소 비교](https://help.altair.com/2024/hwsolvers/rad/topics/solvers/rad/shell_elements_c.htm)

## 3. Q1 — 한 장의 외피와 두께를 얻는 방법

### 3.1 현재 cavity 광선 규칙의 반례

`skin.py`의 `_faces_a_cavity()`는 대표점의 바깥 법선 방향으로 광선을 쏘아 다른 면을 다시 만나면 cavity 쪽이라고 본다. 이는 일반적인 외피 판별식이 아니다.

- 열린 컵의 안쪽 면에서 입구로 나가는 광선은 아무것도 만나지 않을 수 있다.
- 바깥쪽 비드나 오목한 홈에서도 광선이 같은 부품의 다른 외면을 다시 만날 수 있다.
- UV 바운딩 박스 중앙은 trimmed face 안에 있다는 보장이 없다. 구멍 안이나 잘려 나간 영역일 수 있다.
- 면 하나의 대표점은 부분적으로 변하는 벽 두께와 1:N 대향면 관계를 놓친다.

`BRepClass3d_SolidClassifier`는 점이 **재료 솔리드 안에 있는지** 판별하는 도구다. 캔의 빈 내부와 바깥 공기는 모두 재료 밖이므로 이것만으로 inner/outer를 구별할 수 없다. 다만 법선 중 어느 방향이 재료 안으로 들어가는지 확인할 때는 유용하다. 표본이 실제 trimmed face 내부에 있는지는 별도로 확인한다. [OCC solid classifier](https://occt3d.com/dev/doc/refman/html/class_b_rep_class3d___solid_classifier.html), [face classifier](https://occt3d.com/dev/doc/refman/html/class_b_rep_class___face_classifier.html)

현재의 outer-area 비율 0.85 분기, plate의 최대 면 하나 선택, sewing 후 최대 shell 하나만 남기는 규칙도 범용 기준으로 삼기 어렵다. 분할된 평판의 같은 쪽 면 여러 개를 잃거나, 실제로 필요한 분리 패치를 조용히 버릴 수 있다. 최대 shell만 남긴 뒤 원래 keep 목록으로 계산한 메타데이터를 유지하면 실제 출력과 보고서도 달라진다.

### 3.2 권장 분석 순서

1. **원본을 보존한다.** 단위, 솔리드 유효성, 부품 수, 부피, 경계 상자, 면/인스턴스 식별자를 기록한다. 원본에는 큰 tolerance healing을 하지 않는다.
2. **trimmed face 내부에 여러 표본을 둔다.** 작은 면도 최소 표본을 확보하고, 넓은 면·곡률 변화·두께 변화 구역은 추가 표본을 둔다. seam·모서리·법선 특이점은 피하거나 별도 처리한다.
3. **재료 안쪽 방향을 판별한다.** 표본점 `p`의 양쪽 `p ± εn`을 분류해 OUT→IN 방향을 찾는다. `ε`는 CAD 허용오차보다 크고 최소 보존 두께보다 충분히 작아야 한다. 그러한 범위가 없으면 자동 판정을 중단한다.
4. **첫 재료 구간의 출구를 찾는다.** 안쪽으로 들어간 뒤 같은 솔리드에서 처음 IN→OUT이 되는 교점을 찾는다. 여러 재료 구간을 건너 캔 반대편 벽까지 간 거리는 벽 두께가 아니다. 모든 교점을 거리순으로 확인하고 접선 접촉·중복 seam 교점을 처리한다.
5. **대향 패치를 검증한다.** 교점의 법선이 대체로 반대인지, 거리 변화가 타당한지, 역방향으로 원래 패치에 돌아오는지 확인한다. 재료 내부에 얇은 boss가 붙거나 fillet에서 정상 두께 정의가 모호하면 낮은 신뢰도로 분류한다.
6. **면보다 패치 관계로 묶는다.** 표본별 대향 face ID 집합을 이용해 1:N/N:M 관계를 허용한다. 필요하면 두께나 대향 관계가 달라지는 곳에서 면을 분할한다. OCC face 개수가 같을 필요는 없다.
7. **외피 쪽을 선택한다.** 외부임이 확실한 시드 면, 인접성, 대향 쌍의 반대쪽 배제, 캔 축/해석적 원통면 등의 정보를 함께 사용한다. 림 접힘·헤밍·분기부에서는 명시적 keep/drop 지정이 필요할 수 있다. 최대 반경·중심 광선·최대 연결 성분 하나로 결정하지 않는다.
8. **선택 결과를 독립 모델로 메싱한다.** 선택한 표면만 BREP로 내보내 새 Gmsh 모델에 넣거나, 비선택 엔티티가 확실히 배제된 모델을 만든다. 원래 솔리드를 둔 채 Physical Surface만 지정하는 것은 `generate(2)` 대상 제한과 같지 않다.

OCC의 `IntCurvesFace_ShapeIntersector`는 교점, 해당 면, 광선 매개변수를 제공하므로 4단계의 기반으로 적합하다. API가 외피 의미나 두께 신뢰도를 자동 결정해 주는 것은 아니다. [공식 API](https://occt3d.com/dev/doc/refman/html/class_int_curves_face___shape_intersector.html)

구현 구조는 다음과 같이 나누는 편이 좋다. 아래는 의사코드이며 그대로 실행하는 함수가 아니다.

```python
# 각 단계는 CAD 원본 face/part provenance와 실패 사유를 함께 반환한다.
for sample in valid_trimmed_face_samples(face):
    inward = classify_material_side(original_solid, sample)
    exit_hit = first_material_exit(original_solid, sample, inward)
    pair = validate_reverse_pair(sample, exit_hit)
    thickness_samples.append(pair)

patch_graph = build_patch_pair_and_adjacency_graph(thickness_samples)
selected_skin = select_side(patch_graph, external_seeds, keep_drop_overrides)
require_no_unresolved_structural_regions(selected_skin)
mesh = mesh_selected_surfaces_in_fresh_model(selected_skin)
```

실무적으로는 지원 형상군을 선언하는 것이 중요하다. 균일한 캔 벽, 판재형 캡, 얇은 포일을 먼저 지원하고, 두꺼운 돌기·접힌 다층 헤밍·복잡한 분기부는 별도 정책으로 남기는 것이 합리적이다. 어떤 입력에도 쉘 한 장을 반환하는 것을 성공 기준으로 삼지 않는다.

### 3.3 끝단 띠와 진짜 접힘은 구별해야 한다

두 피부를 두께 방향으로 연결하는 단순 절단면은 외피 쉘에서 제거할 수 있다. 그러나 림의 말림·접힘·비드는 하중을 지지하는 판재 경로일 수 있다. 둘 다 “좁은 면”이라는 이유로 함께 지우면 안 된다. 두께 방향 연결면인지, 실제 벽의 연속 구간인지 대향 패치와 인접성으로 구분한다.

평판도 가장 큰 면 하나가 아니라 **선택한 쪽의 연결된 패치 전체**를 유지해야 한다. CAD가 한쪽 표면을 여러 face로 나눴다는 이유로 구조 면적이 줄어서는 안 된다.

### 3.4 두께는 원본 솔리드에서 측정한다

현재 `gauge_elements()`처럼 요소 중심에서 양방향 최근접 교점을 찾아 작은 값을 취하면 중심이 원래 CAD 표면 위에 없을 때 잘못된 두께가 나온다. 곡면을 근사한 요소의 중심은 chord 쪽에 있고, 중립면으로 이동한 절점에서는 한쪽 피부까지 거리가 대략 반두께다.

예를 들어 반경 10 mm, 중심각 0.4 rad의 chord 처짐은 약 0.1993 mm다. 벽 두께가 0.4 mm라면 무시할 크기가 아니다. 이 수치는 기하학적 예시이며 특정 예제 메시의 측정값은 아니다.

권장 방식은 요소/적분 표본을 provenance가 보존된 원본 외피 face에 투영하고, 그 표면점에서 재료 IN→OUT 두께를 측정하는 것이다. 요소당 여러 표본을 써서 변화 폭도 기록한다. 다음을 구분해 저장한다.

- CAD에서 직접 측정한 두께와 측정 신뢰도
- 사용자 지정 공칭 두께 및 CAD와의 차이
- 측정 실패 구역, fallback 적용 면적/요소 수와 사유

스코어 구역의 측정 실패를 조용히 공칭 두께로 채우면 가장 중요한 홈이 사라진다. 원본 두께를 재현하는 모드와 의도적으로 두께를 바꾸는 설계 모드도 구분해야 한다.

### 3.5 외피를 쓸 것인가, 중립면으로 옮길 것인가?

당장은 FR-02에 맞춰 **외피를 기준 표면으로 유지**하는 것이 우선이다. 그때 쉘의 기준면·두께 방향 위치·접촉 외곽을 명확히 해야 한다. 외피 절점에 중심 두께 쉘을 놓으면 실제 재료 위치가 바깥으로 이동할 수 있다.

Radioss의 `/PROP/TYPE1`에는 Ipos로 요소 기준면과 쉘 상·하부 위치를 설정하는 경로가 있다. 공식 설명상 Ipos=3/4는 각각 상부/하부 위치와 관련된다. 일관된 법선, 요소별 두께, 접촉·압력 조건을 갖춘 작은 모델에서 저장소 고정 버전의 동작을 검증한 뒤 외피 기준 위치 정책으로 검토할 수 있다. 코드에 숫자 하나만 넣으면 해결된다고 단정하지 않는다. [공식 속성 카드](https://help.altair.com/hwsolvers/rad/topics/solvers/rad/prop_type1_shell_starter_r.htm)

`BRepOffsetAPI_MakeOffsetShape`는 범용 중립면 추출기가 아니다. 작은 곡률반경, C1 연속성 부족, 자기교차, 모서리 접합 문제가 있으며 offset 결과가 반대 피부와의 가운데라는 보장도 없다. 자동 중립면 경로를 채택하려면 FR-02를 먼저 명시적으로 개정해야 한다. [OCC offset API와 제한](https://occt3d.com/dev/doc/refman/html/class_b_rep_offset_a_p_i___make_offset_shape.html)

현재 `offset_to_mid_surface()`의 평균 절점 법선 이동에도 제한이 있다. 현 구현 함수를 분리 실행한 작은 정육면체 검사에서, 두께 2 mm일 때 각 평면을 1 mm 안쪽으로 옮겨 얻는 모서리와 달리 각 축 이동량은 약 0.57735 mm였다. 정규화된 평균 법선으로 길이 1 mm를 이동했기 때문이다. 즉 **절점 법선 이동은 모서리에서 offset 평면의 교선 구성과 다르다.** 해당 검사는 일반적인 곡면 offset 성공을 증명하지 않는다.

또한 중심에서 바깥으로 향하는지로 면 법선을 개별 반전하는 `orient_outward()` 규칙은 오목한 형상에 일반화되지 않는다. 먼저 공유 변을 따라 방향을 일관되게 전파하고, CAD 법선으로 부호를 고정해야 한다. 닫힌 표면의 signed volume은 보조 검증이 되지만 열린 캔에는 그대로 적용할 수 없다. 절점 이동 후에는 품질·면적·초기 접촉 간격을 다시 평가한다.

## 4. Q2 — 15-solid 어셈블리와 용접

### 4.1 솔리드 분리보다 먼저 부품의 의미를 보존한다

solid 하나가 항상 part 하나는 아니다. 하나의 부품에 여러 solid가 있을 수 있고, 같은 형상의 인스턴스가 다른 위치에 배치될 수도 있다. 가능하면 STEP XDE를 통해 이름, 인스턴스 변환, 부품 계층을 유지한다. `STEPCAFControl_Reader`는 이 목적의 공식 경로다. 이름이 없는 STEP에는 별도 부품 매핑을 둔다. [OCC STEPCAF reader](https://occt3d.com/dev/doc/refman/html/class_s_t_e_p_c_a_f_control___reader.html)

부품별로 `part_id`, 원본 solid/face 식별자, 단위, 배치 변환, 공칭 두께 또는 두께 범위, 재료, 외피 선택 결과를 기록한다. foil·cap·can을 전체 면적 순위로 분류하지 않는다. 비슷한 면적의 face를 정렬해 두께를 대응시키는 현재 assembly 경로는 sewing·fragment 후 대응이 보존된다는 보장이 없다.

### 4.2 접촉한 곳이 자동으로 용접부가 되는 것은 아니다

권장 순서는 **부품별 이상화 → 용접 의도 정의 → 해당 선을 양쪽 면에 imprint/partition → 일치하는 선 메시 → 그 용접선 절점만 공유**다. 단순한 근접·교차 탐색은 후보 생성에 사용한다.

용접 정의에는 최소한 두 부품 ID, 용접선/영역, 허용 간격, 연속 용접인지 간헐 용접인지, 의도된 편심 처리 정책이 있어야 한다. 선언되지 않은 접촉면을 병합하면 분리·미끄럼이 사라진다. 반대로 실제 용접이 면적 접합이라면 한 줄 연결로 단순화해도 되는지 검토해야 한다.

0.1 mm 포일과 1 mm 캡은 두께만 다르게 주는 문제가 아니다. 기준면이 떨어져 있으면 직접 절점 병합은 위치를 옮기거나 편심을 지우는 가정이 된다. 쉘 위치 옵션으로 정합 가능한지 검증하고, 그렇지 않으면 모델링 가정을 명시하거나 솔버의 연결 기능을 쓰도록 규약을 확장해야 한다. 후자는 현재 “용접=merged nodes” 규약의 변경이다. 자체 물리 구현은 필요하지 않다.

### 4.3 현재 assembly 경로에서 우선 확인할 문제

- 모든 표면을 전역 fragment하면 선언되지 않은 접합에도 공통 절점이 생길 수 있다. 용접 대상과 단순 접촉 대상을 분리해야 한다.
- fragment 결과의 2D 영역에 `setdefault`로 최초 owner 하나만 부여하면 겹치는 두 판 중 한쪽 소유권/요소가 소실될 수 있다. **공유 용접선(1D)**과 **겹치는 판 면적(2D)**을 구분해야 한다.
- `_plane_height()`의 지배 면 Z 바운딩 박스 중간값은 평면성 판정이 아니다. `coplanar` 이동을 하기 전에 원래 평면 여부, 법선, 전체 편심 변화를 확인해야 한다.
- assembly 경로의 `enforce_gate`는 일반 `evaluate_mesh_gate()`와 동일한 품질 검사를 보장하지 않는다. SICN·종횡비·최소 변·삼각형 비율을 최종 assembly mesh에도 명시적으로 적용해야 한다.
- 절점 하나를 공유하는 것만으로 구조가 연결되었다고 판단하면 점 접합을 통과시킨다. 표면 내부의 변 연결성과 선언된 용접선 연결성을 따로 검사해야 한다.
- `_check_welds()`에서 guest 기준으로 결과를 저장하면 동일 guest의 여러 용접쌍이 덮어써질 수 있다. `(host, guest, joint_id)` 단위가 필요하다.
- `_seam_fraction()`의 guest 전체 자유경계 대비 공유 끝점 비율은 실제 지정 용접선 길이 대비 연결률이 아니다. 두 끝점 공유만으로 host에 동일한 변이 있다는 것도 보장하지 않는다. 실제 예정 seam의 길이와 양쪽 edge 대응을 검사한다. 50% 기준은 임의의 부분 용접에 보편적으로 적용할 수 없다.

전체 조립체에서 한 변에 세 장이 모이는 T형 용접은 의도된 비다양체 연결일 수 있다. “비다양체 변 0”을 조립체 전체에 무조건 적용할지, 부품별로 적용하고 명시된 용접선은 예외로 둘지 스펙에서 정해야 한다. 예외를 전체 비다양체 허용으로 확대하면 안 된다.

`self_contact=False`로 용접부 초기 접촉 문제를 피한 실험이 있다 해도 압착 전체의 일반 해법으로 채택해서는 안 된다. 접힐 때 생기는 자기접촉이 사라질 수 있다. 용접 인접부의 접촉 제외 범위와 실제 자기접촉을 분리해 검증한다.

## 5. Q3 — 디피처링 규칙과 CATIA 전처리

직사각형 `L × w`에 대해 `2A/P = Lw/(L+w)`다. `L >> w`에서만 폭 `w`에 가까워지고, 정사각형에서는 변 길이의 절반이다. 구멍이 있는 면에서는 둘레 증가로 더 작아질 수 있다. 현재 프록시는 후보 정렬에는 쓸 수 있지만 구조 특징을 삭제할 근거로는 부족하다.

권장 순서는 다음과 같다.

1. **보존 특징을 먼저 지정한다.** 스코어, 용접선, 접촉/하중 지지면, 접힘, 좌굴을 유도하는 비드·넥은 보호한다.
2. **기하학을 바꾸지 않는 정리를 우선한다.** 같은 지지면의 불필요한 CAD 분할 경계를 합치거나 메셔에서 가상 경계로 다룬다. 면 수 감소와 물리적 형상 삭제를 구별한다.
3. **구조화 메싱·국소 분할을 시도한다.** 한 줄로 가능한 좁은 띠를 먼저 살린다.
4. **실제 형상 단순화는 영향 기준으로 결정한다.** 특징 폭·높이·곡률반경을 요소 크기뿐 아니라 판 두께, 접촉 간격과 비교한다. 제거 면적 외에 체적/질량, 단면 형상, 국소 곡률과 두께 변화도 기록한다.
5. **중요한 단순화는 해석 민감도를 확인한다.** 원본을 더 세밀하게 모델링한 비교 케이스와 단순화 케이스의 초기 강성·좌굴 위치·하중 곡선 등을 비교한다. 합격 오차는 벤치마크 목적에 맞춰 정하며 면적 10%로 대신하지 않는다.

곡률에 따른 chord 오차의 작은 각도 근사는 `e ≈ h²/(8R)`다. 허용 형상 오차로부터 요소 길이 상한을 정하는 데 쓸 수 있지만, 그것만으로 비드를 지워도 된다는 결론은 나오지 않는다. 필요한 곡률 해상도와 최소 변 비용 가드가 양립하지 않으면 그 충돌을 보고해야 한다.

CATIA 쪽에서는 원본을 보존한 해석용 파생 형상에서 중요하지 않은 feature를 억제하는 방식을 우선 검토할 만하다. 다만 STEP exporter에 범용 “구조적으로 무해한 필렛 병합” 옵션이 있다고 가정해서는 안 된다. 사용 중인 V5 버전·라이선스·실제 COM 노출 기능을 확인한 뒤 자동화 범위를 정한다. 변환 파일에는 원본 식별자/해시, CATIA 버전, 단위, 변환 설정, 억제한 feature 목록을 연결해 둔다. 기존 Windows 변환 경로는 유지 가능하며, Linux에서 STEP을 받는 것 자체가 이 문제의 핵심 장애물은 아니다.

## 6. Q4 — 0.5 mm healing은 언제 안전한가?

**허용오차와 벽 두께 두 숫자만으로 안전을 보장할 수 없다.** 실제 어떤 면/변을 합치거나 제거하는지와 보존해야 할 최소 간격이 중요하다. `tolerance=0.5`가 반드시 두 피부를 합친다는 뜻도 아니지만, 한 예제에서 합쳐지지 않았다는 사실이 안전성 증명은 아니다.

현재 `occ.remove(..., recursive=False)` 이후 healing이 구멍을 항상 메운다는 가정부터 검증해야 한다. 상위 solid 참조 때문에 제거가 기대대로 되지 않을 수도 있고, sewing은 열린 경계를 맞추는 기능이지 임의의 누락 면을 원래 의도대로 재구성하는 보장이 아니다. OCCT sewing은 free/multiple/deleted edge·face 관련 검사 정보를 제공한다. BREP 유효성 검사 역시 물리적 동등성까지 판정하지 않는다. [Sewing API](https://occt3d.com/dev/doc/refman/html/class_b_rep_builder_a_p_i___sewing.html), [BRepCheck analyzer](https://occt3d.com/dev/doc/refman/html/class_b_rep_check___analyzer.html)

안전한 운영 절차는 다음과 같다.

- 원본을 두께·대향면 분석의 기준으로 남기고 작업 사본을 만든다.
- 실제 틈과 CAD tolerance를 측정한 뒤, 지정된 이웃 면에 최소한의 tolerance로 적용한다. 최소 벽 두께·스코어 잔여 두께보다 충분히 작은 값에서 출발한다. `t_min/10` 같은 값도 시작점일 뿐 보증식은 아니다.
- 각 단계 전후 solid/shell 수, free/nonmanifold boundary, 체적, 부품 소유권, 보존 구멍, 국소 두께 분포를 비교한다. 원본과 수정면 사이의 표본 거리도 기록한다. 표본 거리의 최대값을 엄밀한 Hausdorff 거리라고 부르지는 않는다.
- 바깥/안쪽 대응 패치가 사라졌는지, 얇은 구역의 두께가 0 또는 비정상 값이 되었는지, 다른 부품과 합쳐졌는지 검사한다.
- 불합격이면 rollback한다. 예외를 무시하고 변경 여부도 모르는 형상을 계속 메싱하는 best-effort는 최종 해석 경로에 적합하지 않다.

외피 선택을 먼저 끝내면 이미 제거한 반대 피부와 잘못 봉합할 위험은 줄어든다. 그래도 서로 가까운 림·접힘·다른 부품 사이를 잘못 붙일 수 있으므로 국소 검증은 계속 필요하다.

## 7. Q5 — 5변 이상 필렛과 transfinite

**CAD curve 개수와 논리적인 변 개수는 다르다.** 직사각형의 긴 변이 세 곡선으로 나뉘면 CAD에서는 6변 면이어도 논리적으로는 4변 면이다. Gmsh의 `setTransfiniteSurface`에는 3개 또는 4개의 명시적 corner tags를 주는 경로가 있다. 작은 중간 꼭짓점을 실제 corner로 취급하지 않는 접근부터 검토한다. 복잡한 trim/구멍/주기면이 모두 이 방식으로 해결되는 것은 아니다. [Gmsh 공식 매뉴얼: transfinite 및 t6](https://gmsh.info/doc/texinfo/)

```python
# 면 경계를 검토해 실제 네 corner를 식별한 뒤 사용한다.
# 각 논리적 변은 하나 이상의 CAD curve로 구성될 수 있다.
gmsh.model.mesh.setTransfiniteSurface(
    face_tag, cornerTags=[corner_a, corner_b, corner_c, corner_d]
)
gmsh.model.mesh.setRecombine(2, face_tag)
```

곡선별 `setTransfiniteCurve(tag, numNodes)`를 줄 때 마주 보는 **논리적 변의 총 구간 수**를 맞춘다. 여러 곡선으로 구성된 한 변의 구간 수는 `sum(numNodes_i - 1)`이다. 공유 곡선이 있는 면들을 함께 보고 정수 분할 제약을 정해야 한다. 지금처럼 먼저 처리한 면이 곡선 분할 수를 선점하고 뒤의 면을 건너뛰면 순서 의존성과 실패 구역이 생긴다.

실제 5개 이상의 주요 corner가 있으면 다음을 순서대로 검토한다.

1. 의미 있는 위치에서 사각 패치로 partition한다. 분할 자체가 짧은 변을 만들지 않는지 확인한다.
2. 부드럽게 이어지는 여러 CAD 면에는 `gmsh.model.mesh.setCompound(2, face_tags)` 같은 재매개화 기반 경로를 작은 예제에서 시험한다. 메쉬 단계에서 내부 경계를 넘을 수 있지만 날카로운 특징, 큰 왜곡, 주기적 표면에는 제약이 있다. [공식 매뉴얼 t12](https://gmsh.info/doc/texinfo/)
3. 남는 영역은 비구조화 삼각/쿼드 재결합을 사용하고 최종 게이트로 판정한다. 다른 알고리즘 번호 하나를 모든 형상에 적용하지 않는다. `LOG.md`의 기존 실패 사례도 회귀 대상으로 포함한다.

곡선 길이가 `2 × target`보다 짧다고 무조건 요소 변 하나로 만드는 규칙에도 곡률 조건이 필요하다. 호 길이 대신 실제 절점 간 chord 길이가 최소 변을 만족하는지, chord 오차와 인접 법선 변화가 허용 범위인지 검사한다.

재메싱 3회는 실패 원인별 전략으로 사용한다. 작은 변 때문에 실패했는데 target을 계속 0.75배 줄이면 오히려 악화될 수 있다. 분할 수 정합, 국소 크기 확대, 패치 재구성 등의 원인별 조치를 선택하고, 세 번 실패한 이유와 해당 엔티티를 남긴다. SICN·종횡비 기준을 임의로 낮추지는 않는다.

## 8. Q6 — STEP 스코어 홈을 어떻게 쉘에 옮길 것인가?

**얇은 판의 거시적인 개방·좌굴을 다루려면 잔여 두께장으로 옮기는 접근은 타당한 후보다. 다만 기준면 위치도 함께 필요하다.** 한쪽을 코이닝한 홈은 두께뿐 아니라 실제 중간 위치가 변한다. 홈 바닥 형상을 유지하면서 덱의 쉘 위치까지 잘못 이동하면 홈 깊이 효과를 중복하거나 반대로 없앨 수 있다.

권장 데이터 흐름은 다음과 같다.

1. 원본 솔리드에서 스코어 바닥과 반대 피부 사이의 **잔여 두께**를 측정한다. 홈 깊이 자체를 쉘 두께로 쓰지 않는다.
2. 두께가 바뀌는 경계/밴드를 선택 기준면에 매핑하고 imprint 또는 partition한다.
3. 요소 중심 하나로 얇은 띠를 놓치지 않도록 여러 표본으로 두께 변화를 평가한다. 요소 내부 변화가 크면 경계를 맞추거나 재메싱한다.
4. 실제 재료 위치를 나타내는 기준면/쉘 위치 정책을 두께장과 함께 기록한다.
5. 기존 OpenRadioss 재료·손상 모델로 메쉬 수렴과 파단 위치를 검증한다. 자체 물리를 추가하지 않는다.

요소 내 두께를 면적 평균하면 질량에는 유리하지만 굽힘은 `t³`에 의존하므로 같은 평균이 굽힘을 보존하지 않는다. 매우 좁은 홈을 큰 요소 하나에 평균화하는 것은 해결책이 아니다. 홈 뿌리의 3D 응력 집중·코이닝 잔류응력·가공경화까지 요구하면 현재 쉘 이상화의 표현 범위를 넘는다. 그 경우 추가 재료 정보나 별도 고해상도 검증이 필요하다고 명시해야 한다.

질문에 제시된 0.5→0.3 mm에서 약 −5% 결과만으로 모든 STEP 스코어의 수렴을 선언하지 않는다. 같은 CAD/두께장/재료·손상 설정으로 적어도 세 수준의 메시에서 파단 개시, 개방, 변형 모드와 계산 비용을 비교한다. 손상모델의 요소 길이 의존성도 함께 확인한다. 스코어의 최소 변 예외는 명시된 비용 가드 예외로 기록하고 형상 품질 기준과 분리한다.

### 저장·내보내기에서 이미 확인된 문제

[mesh_data.py](../../crushsim/meshing/mesh_data.py)의 NPZ 저장·복원 경로는 `element_thickness`와 `metadata`를 보존하지 않는다. 해당 구현을 분리 실행한 왕복 검사에서 설정했던 요소 두께 배열은 `None`, 메타데이터는 빈 사전으로 돌아왔다. 요소별 두께를 계산해도 재개 실행이나 후처리에서 잃을 수 있으므로 P0 수정 대상이다. 실제 솔버 전체 경로에서 손실이 발생하는 시점은 별도로 추적해야 한다.

[export_step.py](../../crushsim/post/export_step.py)의 STEP 헤더 한 줄은 요소별 두께 전달 형식이 될 수 없다. STEP 표면과 함께 노드/요소 ID, 연결성, 부품 ID, 두께, 단위, 기준면 정의, 좌표 변환을 담은 sidecar 파일을 보존하고 그 대응을 검증하는 방식을 권한다. 단순한 face 면적 순위로 대응시키지 않는다. 변형 후 면이 참조 형상인지 현재 형상인지도 명시한다. 압착으로 접힌 쉘을 자동 thicken해 유효한 솔리드가 된다고 보장할 수는 없다.

## 9. Q7 — 자세와 하중 의도를 분리한다

CAD에 누워 있다는 사실만으로 압착 방향을 알 수 없고, 주축을 +Z로 맞춘다고 올바른 실험 자세가 되는 것도 아니다. 다음 세 항목을 분리하는 것이 좋다.

- CAD 원래 좌표계와 어셈블리 배치
- 부품의 길이축/캔 축 같은 기하학적 의미
- 해석의 하중 방향, 공구 방향, 지지면과 초기 간격

권장 설정은 `preserve`, `explicit`, `auto_candidate`처럼 의도를 드러내는 모드다. 이는 신규 설정 제안이며 현재 구현된 YAML 필드가 아니다. `explicit`에는 원점과 축뿐 아니라 축 주위 회전까지 정할 두 번째 비평행 방향 또는 회전행렬이 필요하다. 입력 벡터의 영벡터·평행 여부와 회전행렬의 직교성도 검증해야 한다.

자동 후보는 원통/회전면 등 명확한 해석적 형상 정보를 먼저 쓰고, 주축 분석은 보조로 사용한다. 고유값이 비슷한 각형·대칭 형상에서 PCA 축을 확정하지 않는다. 점 표본 PCA는 메쉬 밀도의 영향을 받으므로 솔리드 관성 또는 면적/체적 가중을 고려한다. 어느 경우든 기하학만으로 하중 방향의 의미는 결정할 수 없다.

스펙 FR-02의 자동 +Z 정렬과 현재 무회전 정책 사이에는 실제 불일치가 있다. 먼저 스펙에서 허용 모드와 기본값을 정하고 기존 케이스는 자세를 명시해 결과 재현성을 유지한다. 기본값을 조용히 바꾸지 않는다.

변환은 어셈블리 전체에 일관되게 적용하고 `T_cad_to_analysis`와 역변환을 저장한다. 부품마다 따로 seat하면 조립 간격이 망가진다. 공구·하중 벡터·구속·압력 방향·출력 좌표도 같은 규약을 사용한다. 바닥 착지는 쉘 절점의 `min(z)`뿐 아니라 쉘 두께/위치 옵션이 만드는 실제 접촉 외곽과 초기 간격을 확인해야 한다.

## 10. 적용 순서와 analysis_003에서 확인할 것

### P0 — 잘못된 모델이 조용히 통과하는 경로 차단

1. 일반 STEP 경로에 기존 skin 분석을 연결하되, 모호한 면이나 잘못된 두께를 성공으로 처리하지 않는다. `외피 추출 적용 여부`, 선택/제외 면, 두께 출처를 요약에 남긴다.
2. `element_thickness`와 메타데이터의 저장·복원을 보존하고, 저장 전후 덱 입력에 같은 두께가 도달하는지 확인한다.
3. 전역 healing·면 삭제·최대 shell 선택의 전후 차이를 기록하고 실패 시 rollback한다.
4. final assembly와 offset 후 mesh에 기존 품질 게이트를 적용한다. 이상화 유효성과 수치적 메시 품질은 별도 항목으로 보고한다.

### P1 — 단일 벽을 먼저 검증

알려진 답이 있는 열린 원통 컵·판재·분할된 평면·오목한 외부 비드·trim 구멍을 먼저 사용한다. 두께 0.4 mm인 벽에서 한 피부만 남는지, 끝단 띠와 실제 접힘을 구별하는지, 법선과 두께가 맞는지 확인한다. 의도적으로 애매한 입력은 자동 중단/설정 요구를 검증한다.

그다음 `cylin_can.stp`, `Honda_Can.stp`에 적용한다. 원본과 결과의 단면, 면 ID, 두께 히스토그램, 미확정 영역, 질량/무게중심/관성, 초기 접촉 간격을 비교한다. 쉘 질량과 원본 솔리드 질량 차이는 외피 면적 사용·곡률에 따른 이상화 오차와 의도적인 두께 변경을 구분해 설명한다. 모든 경우에 정확히 같은 질량을 강제하려고 두께를 역산하지 않는다.

### P2 — 어셈블리·스코어·실제 해석

먼저 두 판의 선 용접과 두께가 다른 포일/캡의 작은 조립체로 부품 소유권·편심·공유 변을 검증한다. 이어 실제 15-solid 어셈블리에 적용한다. 좌표가 겹치지만 용접하지 않은 두 판, 하나의 guest에 여러 용접쌍이 있는 경우도 포함한다.

스코어와 압착 해석은 형상·두께·접촉이 확인된 뒤 저장소의 고정 버전 OpenRadioss로 직렬 실행한다. 스타터 검증, 메시 품질, 연결, 기존 에너지 게이트를 함께 보고한다. 기존 이중 피부 해석 곡선은 참고로 남기되 정답으로 맞추지 않는다.

`analysis_003.md`에는 최소한 다음 증거가 있으면 후속 검토가 가능하다.

| 항목 | 필요한 기록 |
|---|---|
| 재현성 | 입력 해시, 코드 커밋, Gmsh/OCC/솔버 버전, 사용 설정 |
| 외피 선택 | 원본→선택 face/patch 대응, keep/drop 사유, 미확정 영역 |
| 두께 | 공칭/측정/사용 두께, 분포, fallback 위치·면적 |
| 형상 변경 | healing/삭제 전후 위상·체적·표본 거리, 보존 특징 |
| 메시 | SICN, 종횡비, 최소 변, 삼각형 비율, 재시도별 조치 |
| 조립 | 부품 소유권, joint별 연결 길이·공유 변, 의도치 않은 연결 |
| 해석 | 초기 간격, 질량, 에너지 게이트, 하중 곡선/파단 위치와 수렴 비교 |

## 11. 이번 답변의 검증 범위

확인한 것은 지정 커밋의 코드·문서와 공식 API 문서다. 작은 수치 재현은 현 구현을 분리한 **정육면체 절점 offset 검사와 NPZ 왕복 검사**이며, 질량/강성 비와 chord 처짐은 별도의 단순 계산이다.

이 환경에서는 실제 Gmsh/OCP를 사용한 해당 STEP 추출·재메싱, CATIA 변환, OpenRadioss 스타터/엔진 실행을 하지 않았다. 따라서 제안한 패치 매칭·용접·쉘 위치 정책이 실제 Honda CAD에서 통과했다고 주장하지 않는다. 라이브러리 공식 문서는 API의 의미를 뒷받침하며, 이 프로젝트에서의 성공 여부는 위 검증을 통해 확정해야 한다.
