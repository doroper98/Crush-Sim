# 여기부터 읽으세요 — 프로젝트 인수인계

새 세션이나 새로 합류한 사람이 **이 문서 하나로 방향을 잡기 위한** 글입니다.
"무엇을 만들었나"보다 **"왜 이렇게 되어 있나"**에 무게를 뒀습니다. 이미
검증해서 값을 치른 사실들이라, 모르면 같은 실수를 반복하게 됩니다.

- 요구사항·ADR: [`SPEC-v2.1.md`](SPEC-v2.1.md) — 위반 시 리뷰 반려
- **삽질 기록: [`LOG.md`](LOG.md)** — 시도했다 실패한 것들과 그 이유
- 벤트 파단 상세: [`VENT_BURST.md`](VENT_BURST.md)
- 폐쇄망 설치: [`OFFLINE.md`](OFFLINE.md)

## 1. 이 프로젝트가 하는 일

캔(원통형·각형 배터리 셀)의 **압착·강도·내압 파단**을 해석하는 파이프라인.

```
CATPart/STEP  →  Gmsh 쉘 메싱  →  OpenRadioss(explicit)  →  결과 변환  →  리포트·3D 뷰어
   (형상)         (게이트 판정)      (물리 계산)              (VTK·CSV)     (HTML)
```

핵심 원칙 두 가지(ADR-01, ADR-02):
- **물리는 자체 구현하지 않는다.** 계산은 전부 OpenRadioss가 한다. 질량-스프링
  같은 자체 적분기는 폴백으로도 금지.
- **계산과 시각화는 분리한다.** 실시간성을 포기하고 정확성을 산다. 뷰어는
  이미 계산된 결과 파일만 읽는다.

## 2. 가장 자주 나오는 질문 — 두께가 있는 STP가 왜 "두께 없는" 메쉬가 되는가

STP를 열어보면 벽 두께가 있는 **솔리드**인데, 메쉬를 보면 종이처럼 얇은
**면**이고, 뷰어에서도 두께가 안 보입니다. 버그가 아니라 **쉘 이상화(shell
idealization)** 라는 판금 해석의 표준 기법입니다.

### 무슨 일이 일어나는가

STP의 솔리드에서 **중립면(mid-surface)** 하나만 뽑아 그 위에 메쉬를 깝니다.
두께는 기하에서 사라지지만 **쉘 요소의 물성값으로 넘어갑니다.**

```
 실제 캔 벽 (STP 솔리드)          쉘 이상화 후
  ┌──────────────┐
  │              │  t=0.6mm   →   ─────────────  중립면 (면 하나)
  └──────────────┘                 t = 0.6mm 는 요소 속성으로 보관
```

`crushsim/geometry/parametric.py`의 `CanShell` / `BoxCan`이 정확히 이 구조입니다
— 형상은 중립면, `thickness`는 별도 파라미터. 반경도 `mid_surface_radius`
(외경 − t/2)를 씁니다.

### 두께는 사라진 게 아니라 계산에 들어가 있다

OpenRadioss 덱의 `/PROP/SHELL` 카드에 두께가 적히고, 다음 세 가지에 전부
반영됩니다:

| 무엇에 | 어떻게 |
|---|---|
| **굽힘 강성** | **t³에 비례** — 두께가 2배면 굽힘 저항은 8배 |
| **막(면내) 강성·질량** | t에 비례 |
| **접촉 두께** | 요소가 t/2만큼 두꺼운 것처럼 접촉을 판정 |

그리고 두께 방향으로 **적분점 5개**(`SHELL_INTEGRATION_POINTS = 5`)를 두어,
벽 안쪽/바깥쪽의 인장-압축 차이(굽힘 응력 분포)까지 계산합니다.

> 그래서 **1T 캔과 10T 캔의 해석 결과는 전혀 다릅니다.** 화면에서 똑같이
> 얇게 보일 뿐입니다. 이게 처음에 가장 헷갈리는 지점이라, 뷰어 하단에
> "쉘 중립면 표시 — 벽 두께 t=Xmm는 쉘 물성으로 강성(굽힘 ∝ t³)·질량·접촉에
> 반영됨"이라는 문구를 자동으로 넣어뒀습니다.

### 왜 솔리드로 안 하고 쉘로 하는가

| | 쉘 (현재) | 솔리드 |
|---|---|---|
| 두께 방향 요소 | 0개 (적분점 5) | 굽힘 표현에 최소 3~5개 필요 |
| 요소 수 | 1.4만개 | 같은 정밀도에 수십~수백만 |
| 시간 간격 | 면내 요소 크기가 결정 | **0.6mm 두께가 결정 → 훨씬 작아짐** |
| 계산 시간 | 분~시간 | 일~주 |

explicit 해석의 시간 간격은 **가장 작은 요소 크기**에 비례합니다. 0.6mm 벽을
솔리드로 3겹 쌓으면 0.2mm 요소가 생기고, 시간 간격이 그만큼 쪼개져 계산량이
폭증합니다. 얇은 판(두께 ≪ 다른 치수)에서는 쉘이 **더 싸면서 더 정확한**
선택이고, 자동차·가전 판금 해석의 사실상 표준입니다.

### 두께가 균일하지 않으면? — 요소별 두께

스코어 벤트처럼 **국부적으로 얇은 곳**은 요소마다 두께를 따로 줍니다
(`/SHELL` 카드의 두께 필드). 벤트 스코어는 0.03mm, 주변 포일은 0.1mm 하는 식.
핀 고정 스타터의 **총질량 비교로 실제로 반영되는지 검증**했습니다.

용접처럼 서로 다른 파트가 붙는 것도 기하가 아니라 **절점 공유(merged nodes)**
로 표현합니다 — 용접부는 원래 한 몸이므로 이게 근사가 아니라 정확한 모델입니다.

### 파생되는 것들

- **변형 형상 STP 내보내기**도 중립면 쉘입니다. CAD에서 쓰려면 두께를
  thicken 해야 합니다. 그래서 STEP 헤더에 두께 값을 적어 보냅니다.
- **STP 임포트 시 디피처링**: 실제 CATIA 파일에는 0.4mm짜리 얇은 띠 면 같은
  게 있어서, 그대로 메싱하면 슬리버 요소가 생겨 게이트를 통과 못 합니다.
  `STEP_HEAL_TOLERANCE_MM = 0.5`로 봉합하고, 최소 모서리 길이를 못 채우는
  좁은 면은 제거 후 재봉합합니다.

## 3. 지금까지 한 일

### 검증 벤치마크 — 3종 전부 통과 (§8)

| | 내용 | 기준 | 결과 |
|---|---|---|---|
| B-1 | 축방향 평균 압괴 하중 | Alexander 이론 ±25% | **+6.4%** |
| B-2 | 링 횡강성 | 탄성해 ±10% | **+1.8%** |
| B-3 | 메쉬 수렴 | 0.5↔0.4mm 피크차 ≤5% | **+1.94%** |

B-3은 쉽게 통과한 게 아닙니다. 완전한 원통은 좌굴 하중이 원리적으로 수렴하지
않아(불완전성 민감도), **0.2mm 불완전성을 심어** 모든 메쉬가 같은 물리적 모드로
좌굴하게 만든 뒤에야 수렴했습니다. 접힘 파장 4√(Rt)≈7.3mm를 반파장당 5요소
이상으로 분해해야 한다는 계산이 근거입니다.

### 해석 트랙

- **압착(LC-1/LC-2)**: 축방향 압궤, Honda 각형 캔 측면·넓은면 압착, 파이프
  롤러 압착, 원통 캔 심압입
- **성형(LC-4)**: 2170 회전 비딩 — 토러스 롤러가 캔을 공전하며 홈을 냅니다.
  4방향 압입 → 궤도 → 대향쌍 → 점진 피드 → 내부 아버까지 5회 반복하며
  실제 공정에 가깝게 개선
- **내압(LC-5)**: 2170 스웰 10 MPa — 이론 후프 응력과 **2% 이내** 일치로
  `/PLOAD` 부호 규약 확정
- **벤트 파단(LC-6)**: 각형 셀 스코어 벤트. v1→v5 다섯 번 반복. 상세는
  [`VENT_BURST.md`](VENT_BURST.md), 요약은 아래 §4

### 도구

- **웹 UI** (`csim ui`): 케이스 편집, 실행 큐(직렬 실행·취소), 결과 목록
- **ComfyUI식 워크플로 그래프**: 형상이 **캔 → 캡 → 벤트** 체인으로 조립되어,
  압착 해석은 캔에서 끝나고 벤트 해석은 캡·벤트가 붙는 구조가 그래프 모양으로
  드러납니다. 여러 노드를 물리면 조합 스윕이 자동 생성됩니다. 결과 노드가
  실행 상태와 리포트·뷰어·STP 링크를 실시간으로 보여줍니다.
  (`configs/graphs/honda_pipe_crush.json`, `vent_burst_study.json`)
- **3D 뷰어**: 자체 완결형 HTML. 프레임 슬라이더, 단면, 파트별 투명도,
  원형(변형 전) 겹쳐보기, 압력-시간 그래프, 주요 치수, 모바일·태블릿 대응.
  생성물은 [`../viewers/`](../viewers/)에 보관
- **폐쇄망 배포**: 폰트 로컬 번들 + pip wheelhouse 오프라인 설치

## 4. 절대 다시 헤매지 말아야 할 것들

값을 치르고 알아낸 사실들입니다.

### 덱 문법 (검증 완료)

- **`/PLOAD`는 양수 Fscale_y가 바깥쪽(팽창)** 입니다. 음수로 하면 캔이
  안쪽으로 찌그러집니다 — 실제로 한 번 그렇게 돌렸습니다.
- **요소별 두께**는 절점 ID 뒤에 `f20(phi) + f20(thk)`. `/SHELL`(쿼드)은 90자,
  **`/SH3N`(삼각형)은 80자** — 길이 가드를 요소 타입별로 잡아야 합니다.
- 요소 블록에는 **제목 카드를 넣으면 안 됩니다** (ERROR 100101).
- `/ANIM/SHELL/TENS/STRESS/ALL`은 고정 버전 엔진을 **세그폴트**시킵니다.
- 스타터 실행에는 `LD_LIBRARY_PATH`(hm_reader, h3d)와 `RAD_CFG_PATH` 필요.

### 해석 판정

- **파단 해석의 에너지 오차는 원래 커집니다.** 요소를 지우면 그 내부에너지가
  수지에서 빠지기 때문입니다(LC-6: 25개 삭제 4.9% → 553개 삭제 13.0%).
  버스트 케이스는 `stop_on_energy_error: false`를 씁니다. 값이 틀린 게
  아니지만 파단압을 인용할 때 **함께 언급해야** 합니다.
- **벤트 개방 판정은 개구 유동 면적 25%** 도달 시점입니다. "스코어 요소 전량
  파단"으로 잡았다가 실패했습니다 — 호 끝의 요소 하나가 살아남아(180개 중
  179개) 판정이 아예 안 나왔고, 요소 개수는 메쉬에 따라 변하는데 면적은
  안 변합니다.
- **메쉬 게이트의 최소 모서리 0.3mm는 품질이 아니라 비용 가드**입니다
  (시간 간격을 좌우). 의도적으로 세분한 sub-mm 형상에 한해 낮출 수 있게
  `min_edge_limit`을 두었고, SICN·종횡비 같은 품질 기준은 건드리지 않습니다.
- **엔진 콘솔의 에너지 오차와 최종 시간이력 수지는 다릅니다.** 판정은
  T01 수지(마찰 접촉 에너지 포함) 기준입니다. 콘솔 값을 보고 보고하면 틀립니다.

### 벤트 파단 요약

| 단계 | 무엇을 배웠나 |
|---|---|
| v1 자유 캔 | 넓은 면이 부풀어 **벽이 1.22 MPa에 먼저 찢어짐** → 젤리롤·모듈 구속 필요 |
| v2 벽 구속 | 3 MPa에서 파단 0건 → 원래 벤트 설계가 과도하게 강함(설계 소견) |
| v3 레이저 스코어 | 2.10 MPa 개방, 단 **테두리 전체 스코어라 플랩이 통째로 방출** |
| v4 용접 포일 + X 스코어 | 0.71 MPa, 교차점에서 개시, 캔 무손상 — 실물 구조 재현 |
| v5 스코어를 실제 기하로 각인 | 0.51 MPa, 개방 단계 파단 **100%가 스코어 위** |
| v5 + 0.5mm 세분 | **0.303 / 0.385 MPa — 실무 기준 메쉬** |
| v5 + 0.3mm 세분 | 0.287 / 0.366 — medium 대비 5%, **수렴 확인** |

균일 메쉬는 스코어가 1요소 폭이라 **파단압을 약 70% 과대평가**합니다.

### 운영

- **솔버는 반드시 직렬로 돌립니다.** 4코어에서 엔진 2개를 동시에 돌리면
  스핀락으로 ~100배 느려집니다. UI 큐가 이걸 강제합니다.
- **컨테이너는 재시작되면 실행 중인 솔버와 bash 대기자를 죽입니다.**
  장시간 해석에는 재시작을 견디는 예약 체크인을 함께 걸어야 합니다.
- `ruff format`은 저장소 설정이 없어 무관한 코드를 재포맷합니다.
  **`ruff check`만** 쓰세요.

## 6. 결과를 바꾸고 싶을 때

검증 부담이 낮은 순서입니다. 자세한 설명은
[`VENT_BURST.md` §변경](VENT_BURST.md)에 있습니다.

1. **케이스 YAML** — 치수·하중·메쉬. 설계 검토는 여기서 끝납니다.
2. **재료 카드** — `sigma_y`·`uts`·`n`이 하중 수준을, `eps_p_max`가 파단
   시점을 정합니다. 현재 카드는 전부 `verified: false`(문헌값)라 리포트에
   trend-only 워터마크가 자동으로 붙습니다. **실측 인장 데이터가 들어오면
   카드만 교체하면 됩니다** — 코드는 안 바뀝니다.
3. **게이트 기준** (`units.py`) — 판정이 바뀌므로 B-1~B-3 재실행 필수.
4. **물리 모델** (`deck/writer.py`) — 스타터 검증 → 이론 대조 → 골든 덱
   바이트 동일 확인 → 벤치마크 재실행.

**정량 예측의 전제는 2번입니다.** 지금 모든 수치는 문헌 물성 기반의
경향값(trend-only)이고, 상대 비교(설계 A vs B)는 신뢰할 수 있지만 절대값은
실측 보정 후에 인용해야 합니다.
