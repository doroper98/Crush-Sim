## 0. UI_001에 대한 판정과 정정

UI_001의 **필수** 항목은 전부 수용한다. 권고안이 작성된 뒤 바뀐 사실 하나를 정정한다.

| UI_001 문장 | 정정 (analysis_005 §1.1, 2026-09-07 저녁) |
|---|---|
| "30분·10%를 동시에 만족하는 프리셋이 확정되기 전에는 '30분 목표 기본 설정' 배지를 붙이지 않는다" | **확정됐다.** `lc6_pris_vent_burst_v5_preset` = 스코어 0.5 mm + `solver.end_time 1.8e-3`: 엔진 13.6분, 총 14.4분(4코어 컨테이너), 0.3 mm 대비 +5.7 % / +5.3 %. 배지는 붙이되 근거를 함께 표시한다: **"30분 목표 설정 · 컨테이너 4코어 실측 14분 · 기준 노트북 미교정"**. 0.65 mm 탐색 후보는 등록하지 않는다(더 느렸다). |
| §6.4 "0.5 mm는 엔진 약 39분·시간 목표 초과" | 전구간(3.5 ms) 런에만 해당. 프리셋(1.8 ms 종료)이 기본이고, 전구간은 고급 옵션 "개방 이후 찢김까지 계산 (약 40분)"으로 남긴다. |

범위: UI_001 §16의 **P0 → P1 → P2**를 이번 구현 범위로, **P3**는 백로그로 둔다.
첫 세로 흐름(§20)을 끝까지 연결하는 것이 완료 조건이다:

> 각형 캔 벤트 템플릿 **또는** STEP 업로드 → 목적 선택 → 필수 조건 확인 → 사전 검사·예상 시간
> → 불변 실행 → 판단 문장이 있는 결과 → 조건 하나 바꿔 비교.

이번에 **하지 않는 것**: 전기저항·열(capability에 `available: false`로만 존재), 자동 최적안,
같은 순번끼리 비교 모드, 다중 탭 개정 충돌의 완전한 해결(개정 번호 검출까지만),
관성 주축 자동 회전, 모바일에서의 제출.

## 1. 고정된 설계 결정 (구현자가 다시 논의하지 않는다)

### 1.1 파일 배치

```
crushsim/ui/
  server.py           얇게: 라우팅만. 아래 모듈에 위임
  capabilities.py     GET /api/capabilities 의 내용(단일 근거)
  assets.py           업로드·검사·미리보기(runs/_ui/assets/<id>/)
  graphc.py           그래프 → 케이스 dict 컴파일 (브라우저 compileGraph의 Python 이식, 정본)
  preflight.py        정규화·검사·해시·예상 시간·조합표
  executions.py       불변 스냅샷·직렬 큐·상태·취소 (기존 워커를 일반화)
  results.py          결과 계약(지표·목표 판정·유효성·검증 근거·타이밍)
  estimates.py        실측 기반 시간 추정표
  errors.py           오류 계약(code/message/severity/field_path/actions)
  storage.py          상태 파일의 원자적 쓰기(임시 파일 + os.replace)
  viewergen.py        (기존) + 판단 문장·신뢰 블록 주입
  static/
    index.html        작업실 골격(HTML). 스크립트는 아래 파일로 분리 — 빌드 없음, CDN 없음
    app.css           §12 토큰과 컴포넌트
    app.js            AppState/ApiClient/GraphModel/GuidedSetup/GraphView/Inspector/RunStore/ResultPresenter
    render3d.js       viewer_template의 WebGL 렌더러를 추출한 공용 모듈(작업실 미리보기 + 뷰어)
    viewer_template.html (기존) — render3d.js를 인라인으로 포함해 **독립 HTML**을 유지
```

`static/` 아래 JS는 전부 `node --check` 대상. 외부 요청 0건(폰트는 기존 `fonts.css`).

### 1.2 저장 위치와 식별자

| 것 | 위치 | 식별자 |
|---|---|---|
| 업로드 형상 | `runs/_ui/assets/<asset_id>/original.stp`, `inspect.json`, `preview.json` | `asset_id` = sha256(내용) 앞 12자. 같은 내용은 같은 id |
| 실행 스냅샷 | `runs/_ui/executions/<exec_id>/case.yaml`, `snapshot.json`, `state.json`, `log.txt` | `exec_id` = `<케이스명>_<sha256(입력해시+솔버 노드 id) 앞 6자>`. 같은 이름의 케이스 두 개는 `DUPLICATE_CASE_NAME`(block)으로 막는다 |
| 런 산출물 | `runs/<exec_id>/` (파이프라인이 씀) | 기존 `/api/runs/{name}/…`이 그대로 동작 |
| 그래프 초안 | `configs/graphs/<name>.json` (기존) | `schema_version: 2`, `revision: n` 추가. v1(필드 없음)은 읽기 가능 |
| 프리플라이트 | 메모리 + `runs/_ui/preflights/<id>.json` | `preflight_id` = uuid4 |

`runs/`는 git 제외다. `_ui/`도 그 안에 둔다.

### 1.3 실행의 진실은 스냅샷이다

- `POST /api/executions`는 `preflight_id + input_hash + idempotency_key`를 받아 **스냅샷
  케이스 YAML**(정규화된 dict, `output.dir: runs/<exec_id>`)을 쓰고 큐에 넣는다.
  같은 `idempotency_key`는 같은 `exec_id`를 돌려준다(U19).
- 워커는 `python -m crushsim all -c runs/_ui/executions/<exec_id>/case.yaml`만 실행한다
  (기존과 같은 CLI, 다른 경로). `configs/cases/`는 건드리지 않는다(U20).
- 기존 `POST /api/runs/{case_file}`는 남기되 내부에서 케이스 파일을 스냅샷으로 복사해
  같은 큐로 보낸다. UI는 더 이상 이 경로를 쓰지 않는다.
- 큐는 프로세스 전역 하나, 직렬(솔버 병렬 금지, `CLAUDE.md`).

### 1.4 컴파일 정본은 서버다

`graphc.compile_graph(graph) -> {cases:[{file,name,yaml,changed_vs_first,preset_id,
preset_applied,preset_overridden}], errors:[Error]}`.
브라우저 `compileGraph()`는 남기되 **표시용**이고, 실행 이름·조합 수·예상 시간은 전부
`/api/preflights` 응답에서 온다. `tests/test_ui.py::test_prebuilt_graphs_compile_to_valid_cases`
를 Python 컴파일러로 옮겨 `configs/graphs/*.json` 전부가 `load_case`를 통과하는지 검사한다.

### 1.5 물리·게이트는 UI가 정하지 않는다

게이트 한계는 `crushsim/units.py`에만 있다. UI는 결과 계약의 `validation`을 그대로
표시한다. 시간 예산 초과는 **경고**이고 실행을 막지 않는다(UI_001 §8.2). 실행을 막는
것은 `severity: block`인 검사뿐이다.

### 2.2 자산

`POST /api/assets` (multipart, 필드 `file`) → `202 {"asset_id","status":"importing"}`.
서버는 즉시 백그라운드 스레드에서 `inspect_step` + `extract_shell_skins` 요약을 만들고,
미리보기 메쉬(`mesh_step_surfaces` 목표 3 mm, enforce=False)는 **자식 프로세스**에서
만든다(`python -m crushsim.ui.assets <asset dir>`) — gmsh는 `initialize()`에서 SIGINT
핸들러를 걸기 때문에 워커 스레드에서 부르면 "signal only works in main thread"로 죽는다
(WP1에서 확인, `docs/LOG.md` §13). 결과는 `inspect.json`/`preview.json`.
파일명은 `display_name`으로만 보관하고 경로에는 쓰지 않는다(U42).

`GET /api/assets/{id}` →

```json
{"id":"…","display_name":"Honda_Can.stp","content_hash":"sha256:…","bytes":72105,
 "status":"ready|importing|failed","error":null,
 "units":{"declared":"mm","confirmed":false,"plausible":true},
 "dimensions_mm":[120.5,12.56,65.0],
 "parts":[{"index":1,"kind":"hollow","volume_mm3":7447.2,"wall_thickness_mm":0.38,
           "uniformity":0.74,"role_suggestion":"can"}],
 "diagnostics":[{"code":"SINGLE_SOLID","severity":"info","message":"…"}],
 "preview":{"url":"/api/assets/<id>/preview","triangles":7615}}
```

`GET /api/assets/{id}/preview` → `{"positions":[...],"indices":[...],"bbox":[...]}` (표시용,
원본이 아님을 응답에 `"lod":"preview_3mm"`로 표시).

`plausible`은 최대 치수가 5~500 mm 범위면 true. 아니면 `UNIT_CONFIRMATION_REQUIRED`(block).

### 2.3 그래프 초안 v2

기존 `{nodes:[{id,type,x,y,params}],edges:[{from,to,port}]}`에 다음을 **추가**한다(기존 키 유지):

```json
{"schema_version":2,"revision":7,
 "purpose":"vent_burst",
 "mesh_preset":"lc6_preset_30min",
 "asset_refs":{"<node id>":"<asset_id>"},
 "targets":[{"metric_key":"vent_opening_pressure","lower":0.3,"upper":0.5,"unit":"MPa","inclusive":true}],
 "provenance":{"<node id>.<param>":"geometry|template|user|unknown"},
 "confirmations":{"material":true,"support":true,"load_direction":true},
 "nodes":[…],"edges":[…]}
```

`mesh_preset`은 §2.1의 `mesh_presets[].id`이고, 솔버 노드의 `params.mesh_preset`이
있으면 그것이 우선한다. 프리셋은 **기본값이지 강제가 아니다**: 그래프가 비워 둔 값만
채우고, 사용자가 적어 넣은 값은 그대로 두고 `preset_overridden`으로 보고한다(WP1에서
확인: 강제로 덮으면 0.3 mm 스윕 가지가 프리셋의 0.5 mm로 바뀌어 두 케이스가 같아진다).

미지의 노드 타입·필드는 **보존**하고 `read_only: true`로 열어 실행을 막는다(U14).
`PUT /api/graphs/{name}`는 서버 파일의 `revision`이 요청의 `base_revision`보다 크면
`409 REVISION_CONFLICT`(U41, 검출까지).

### 2.4 `POST /api/preflights`

요청: `{"graph": <GraphDraft v2>, "solver_node_id": "n7"|null}`.
응답:

```json
{"id":"…","input_hash":"sha256:…","runnable":true,
 "purpose":"vent_burst","preset_id":"lc6_preset_30min","graph_revision":7,"targets":[…],
 "cases":[{"exec_id":"box_vent_a1b2c3","name":"…","yaml":{…},"preset_applied":{"solver.end_time":0.0018},
           "preset_overridden":{},"changed_vs_first":{"geometry.vent.score_thickness":[0.03,0.04]}}],
 "combinations":{"mesh":1,"material":1,"load":2,"total":2},
 "checks":[{"code":"MATERIAL_NOT_VALIDATED","severity":"review","message":"…","node_id":"n3","actions":["choose_material"]}],
 "estimate":{"per_run_min":[12,17],"total_min":[24,34],"basis":"lc6_preset_30min 실측 14.4분 ×0.85~1.2",
             "hardware":"4-core container","over_budget":false,"available":true,"reason":null},
 "policy_version":"2026-09-07"}
```

검사 목록(최소):

| code | severity | 조건 |
|---|---|---|
| `GRAPH_INCOMPLETE` | block | 솔버에 메쉬·재료·하중 미연결, 형상 체인 시작이 캔이 아님 |
| `PURPOSE_UNAVAILABLE` | block | `available: false` 목적 |
| `GEOMETRY_UNSUPPORTED` | block | 목적의 `supported_geometry` 밖 |
| `ASSET_NOT_READY` | block | 자산 status ≠ ready |
| `UNIT_CONFIRMATION_REQUIRED` | block | 자산 `units.plausible == false` 이고 미확인 |
| `THICKNESS_MISMATCH` | block | STEP: 케이스 두께가 게이지 벽두께와 10 % 넘게 다름(`STEP_THICKNESS_MISMATCH_MAX`) |
| `INVALID_VALUE` | block | `load_case` 로더 오류(ConfigError 메시지 첨부), 잔여 두께 ≥ 포일 두께 등 |
| `MATERIAL_NOT_VALIDATED` | review | 재료 카드 `verified: false` |
| `TIME_BUDGET_EXCEEDED` | review | 추정 상한 > 30분 |
| `ESTIMATE_UNAVAILABLE` | info | 실측 자료 없는 템플릿·형상 |
| `PRESET_APPLIED` | info | 자동 적용된 메쉬/종료 시점 프리셋과 근거 |

`input_hash` = sha256(정규화 YAML 텍스트 + 자산 content_hash들 + `policy_version`).
검사에 `DUPLICATE_CASE_NAME`(block, 케이스 이름 충돌)을 추가한다. 자산이 `status: failed`면
`ASSET_NOT_READY`가 아니라 자산 자신의 `error.code`/메시지/행동을 그대로 block으로 올린다
(끝나지 않을 기다림을 안내하지 않는다).
`over_budget`은 **1건 기준**이다(GOAL.md의 30분은 해석 1건의 예산이다) — 위 예시의
2건 24~34분이 `over_budget:false`인 이유. 사용자 값이 프리셋을 대체했으면 실측 표본과
다른 모델이므로 `available:false`(`ESTIMATE_UNAVAILABLE`)로 내린다.

### 2.5 실행

`POST /api/executions` `{"preflight_id","input_hash","idempotency_key"}` →
`201 {"executions":[{"exec_id","state":"queued","queue_position":1}]}`.
해시 불일치 → `409 STALE_PREFLIGHT`(U18). 같은 idempotency_key 재요청 → 같은 응답(U19).

`GET /api/executions/{id}` →

```json
{"exec_id":"…","state":"queued|running|cancelling|completed|failed|cancelled|interrupted",
 "stage":"geometry|meshing|deck|solver|post|report|null","engine_progress_pct":41.5,
 "queue_position":null,"timestamps":{"submitted":"…","started":"…","finished":"…"},
 "timing":{"queue_seconds":0,"execution_seconds":864,"stage_seconds":{"solver":813}},
 "diagnostics":[…],"artifacts":{"report":"/api/runs/<id>/report","viewer":"/api/runs/<id>/viewer","csv":"/runs/<id>/force_displacement.csv"},
 "snapshot":{"input_hash":"…","case_yaml_url":"/api/executions/<id>/case"}}
```

상태 규칙(UI_001 §9.1·§9.2): 서버 재시작 후 프로세스가 없고 `pipeline_summary.json`이 없으면
`interrupted`. 로그 파일만으로 `running`을 복원하지 않는다(U25).

`POST /api/executions/{id}/cancel` → `cancelling`; 프로세스 종료 확인 후 `cancelled`.

`GET /api/executions` → `{"items":[…]}` (큐·활성·완료 통합, 완료는 `runs/*/pipeline_summary.json`
+ 스냅샷 존재로 판정; 스냅샷 없는 옛 런은 `legacy: true`).

| `peak_load_N` | `post.metrics.peak_load_N` | N | `peak_load_v1` |
| `absorbed_energy_J` | `post.metrics.absorbed_energy_mJ / 1000` | J | `absorbed_energy_full_stroke_v1` |
| `load_displacement_curve` | `force_displacement.csv` | N vs mm | `load_displacement_v1` |
| `pressure_time_curve` | 덱 FUNCT CAN_PRESSURE_RAMP (viewergen `_pressure_curve`) | MPa vs s | `pressure_ramp_v1` |

미개방이면 `vent_opening_pressure.value = null`, `unavailable_reason: "NOT_REACHED_AT_MAX_PRESSURE"`(U29).

`validation`:

| 필드 | 규칙 |
|---|---|
| `model_validity` | `invalid`: 이상화 게이트 실패·연결성 오류·솔버 실패·NaN. `valid`: 그 외 완료. `unknown`: 요약 없음 |
| `scope_status` | `verified`: 재료 verified **그리고** 사용 프리셋에 `evidence`가 있음. `unverified`: 그 외. `out_of_scope`: 목적 unavailable |
| `diagnostics` | `MATERIAL_NOT_VALIDATED`, `ENERGY_ERROR_ABOVE_GATE`(비치명, 값 첨부), `ADDED_MASS_ABOVE_GATE`, `KINETIC_ABOVE_GATE`, `TIME_BUDGET_EXCEEDED_ACTUAL`(실측 > 30분), `MODEL_DISCONNECTED`, `MASS_MISMATCH` |
| `references` | 프리셋 evidence 문자열, 벤치마크(B-1~B-3) 링크 |

`target` 판정은 원값으로(U30): `within | below | above | none | unavailable`.

`judgement` (서버가 문장을 만든다, UI_001 §10.1 표 그대로):

```json
{"sentence":"개방 압력은 0.385 MPa로, 목표 0.30–0.50 MPa 안에 있습니다.","status":"within",
 "caveat":"재료 모델이 검증되지 않아 참고용으로 표시합니다."|null}
```

### 2.7 오류 계약

모든 4xx/5xx 본문: `{"code","message","severity":"block|review|info","field_path"|null,"node_id"|null,"actions":[…],"detail":"<원문 예외>"}`.
`errors.py`가 `ConfigError→INVALID_VALUE`, `GateFailure→GATE_FAILED`, `GeometryError→ASSET_UNSUPPORTED`,
`MeshingError→MESH_FAILED` 매핑을 가진다. `HTTPException(detail=str)`을 새로 만들지 않는다.

## 5. 구현 세션(Opus)이 지킬 것

1. `CLAUDE.md`를 먼저 읽는다. `git fetch origin main` 후 시작. 브랜치는 `claude/ui-wp<N>`.
2. 문서·계약이 코드와 다르면 **이 문서를 고치고** 그 이유를 커밋 본문에 적는다. 조용히 다르게 만들지 않는다.
3. 검사: `ruff check crushsim tests`(`ruff format` 금지), `node --check static/*.js`, `python -m pytest -q`.
   솔버는 절대 병렬로 띄우지 않는다. 실제 런이 필요하면 `lc6_pris_vent_burst_v5_preset`(14분) 하나만.
4. 실패한 시도는 `docs/LOG.md`에 바로 적는다(§13). 커밋 본문에 "시도했다 실패한 것"을 쓴다.
5. 커밋·PR에 모델 식별자를 넣지 않는다. PR은 draft로 만들고 이 문서의 완료 조건 체크리스트를 본문에 붙인다.
6. 물리·게이트·덱 생성(`crushsim/deck`, `meshing`, `units.py`)은 건드리지 않는다. 필요하면 멈추고 보고한다.
7. 사용자 문구는 UI_001 §17 표를 그대로 쓴다. 영어 예외 문자열을 화면에 직접 내보내지 않는다.
